Delivered contract (see `docs/code-language.md` "Exported package functions" / "Passing functions" in the #810 diff):
- `pub` generic functions (`$T`) specialize across packages; the specialization resolves private helpers/types/constants in the DEFINING package (caller names and import aliases cannot capture them); canonical specialization identity, reuse across diamond imports, invalidation when a defining package changes; errors point at the importing call plus the definition.
- Callable parameter type `fn(value: T) -> R` (0 or 1 result, explicit input types, no defaults or `from`/`split` bindings; not optional, not in containers, not behind pointers). Arguments: a named function or a capture-free inline function `(v: int) => v * 2`, `(v: int) { return v*2 }`, `fn(v: int) -> int { ... }` (only in call-argument position). Synchronous only: may be called or forwarded to another callable parameter; cannot be returned, stored, queued, put in records/containers or passed to unknown host APIs. Compiler emits direct calls; no closure objects.
- Both compiler stages: stage zero (C: `src/language/semantic_*.c`, `callable_headers.*`, `signature_reader.c`, `grammar.js` + generated parser, `src/authoring/source_package_{exports,prepare}.c`, catalog) and stage one (new `tools/compiler/package_compiler/Generics.chibi`, 970 lines; edits to Behavior/Body/Compile/Queries/References/Scalar/Steps `.chibi`). Scalar-facts path uses the same specializer (numeric helper `Remap` passes LLVM validation and an independent integer oracle).
- Explicitly NOT done: captured/escaping closures, stored function values, multi-result callbacks, exported generic record/type factories, constraints syntax, inline functions outside call arguments, real GPU/material/shader execution (only CPU composition + scalar facts + LLVM IR validation), the legacy `CompileBehaviors`/mixed-package route (documented boundary in `docs/package-compiler.md`).
