# Authored library acceptance after the frozen compiler candidate

Source assessment only, 2026-10-23. No tests, compiler invocation, code import or implementation ran for this map. The current candidate remains tree `1a59410022d128108e7744cf2b5641047a44d713`. Its local Starter/Terrain Lab acceptance is distinct from general shipped-default readiness. The original request to finish library/system support is still open.

## Current boundary and existing oracle

The frozen game compiler declares all library signatures before bodies and assembles actual dependency edges. It supports flat numeric/bool/string records without defaults, positional source calls with trailing literal defaults, scalar/record results, and same-library recursion. `docs/package-compiler.md:239-260` documents the limits; `Behavior.chibi:483-527,541-624,687-689` enforces them. Do not infer general library parity from a successful flat-library fixture.

Use the existing source-catalog/native preparation route as the reference: `test/language/package_compiler_chibi.c:6614-6791` (`libraries_with_results`) builds the catalog and native oracle, compiles the same source through both package-compiler providers, loads the closure and compares observable execution through bytecode and the selected compiled backend. `library_rejects_catalog` at 7087-7141 distinguishes oracle-valid and oracle-invalid rejections. Establish reference validity for each proposed new fixture before changing its expected self-hosted outcome. A source-preparation failure must not count as a rejection test passing.

The existing rich-native named-argument cases at 5945-6167 cover native calls; they are not authored-source named-argument coverage. `Steps.chibi:2181-2220` still evaluates source arguments by ordinal and supplies only omitted trailing defaults.

For nested record ownership, start from native `record_runtime_owned_return_and_value_copy` (`record_runtime.c:237`) and cross-library record/module helpers. For defaults and constants, `record_semantic.c` already distinguishes compile-time validity from execution; semantic assertions alone do not prove a runnable library generation. For linked source bodies and cache invalidation, preserve `modules.c` and `library_generations` checks that replacing a used dependency invalidates the consuming generation while replacing an unused library does not.
