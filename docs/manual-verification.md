# Editor verification

## Required automated gate

```sh
make test
# Alias for the same gate:
make ui-integration
```

This builds in `build/` with sanitizers, warnings and ccache enabled. The suite
runs model/command checks and real native ImGui interactions in a hidden window.
The UI smoke test opens the behaviors folder and InputBehavior using rendered
asset-card centers, then asserts the active Behavior Asset, Node Canvas state and
expected event node. It ignores personal ImGui layout settings. The app's
resize scenario injects a press/drag/release and asserts a 240-pixel pane change.
A working native graphics backend is still required; hidden-window is not
GPU-free execution.

Exit status and assertion output are the evidence. To retain a log:

```sh
make test > /tmp/c-blueprints-test.log 2>&1
```

No screenshots or video are required or generated by the suite. The current
smoke test does not yet prove every editor function; see `PLAN.md` for the next
behavioral slices. Manual walkthroughs help diagnose usability but do not
replace automated interaction assertions.

## Optional diagnostics

The native app accepts `--help`, `--headless`, `--frames <count>`, `--fps <rate>`
and `--screenshot [path]`. A screenshot defaults to three frames and
`/tmp/c-blueprints-screenshot.png`:

```sh
build/app --screenshot /tmp/c-blueprints-screenshot.png
build/app --headless --scenario resize-pane
build/app --headless --scenario authoring
```

The surviving assertion scenarios run without recording. `--record` and the
`record-evidence` / `record-resize-pane` make targets have been removed.
