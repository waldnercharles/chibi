# Source-census caller and adoption proposal

Status: **source/design trial only; not implemented or accepted native evidence.**
Written 2026-11-05 against repository HEAD
`5b283f5873173f845e2120820711ac1461a2ad1f`, tree
`03e3ecf37eb76232d433ff8864c0a5027d7ae04a`.

The earlier unpublished caller was lost. `Main.chibi` is a new, explicit caller,
not a recovered copy. Its incidental length is not a compatibility requirement.
The current v3 producer still rejects this program. This proposal changes no
compiler, generated transport, backend, native harness or production default.
Independent review and every implementation/acceptance gate below remain open.

## Purpose and boundary

Make the first real vNext consumer count actual immutable source bytes. Chibi
validates the frame, loops over every payload byte, counts physical and nonblank
lines, and calls C once with the complete report. C supplies one live immutable
buffer to `Census`, prints the report/error, and releases its buffer after return.
There is no per-byte foreign call, C census, Python-precomputed line-count input,
managed string conversion, hash, allocation or source parsing in the byte loop.

A preparer, outside the timed census run, gathers/pins the original source
closure and frames its exact bytes. A sidecar maps record ordinals/offsets and
package IDs to canonical paths and source hashes. The frame does not itself prove
provenance, path uniqueness, import closure, valid UTF-8 or correct target text.
Those remain preparer/source-identity checks. C must not generate this framing or
inspect/count its records; it reads the prepared file as an opaque byte buffer.

This is a real byte-processing tool, not yet a complete replacement for the
Python filesystem Gather census. Adoption must retain discovery/identity work
until Chibi has a justified replacement. Its output can replace line counting,
not the independent identity fence. Nonblank does not mean noncomment.

## Exact input format: CCN1, native-driver static-Gather profile

All frame integers are unsigned 32-bit little-endian; payloads are untouched
bytes, not strings. No padding, sentinel byte or implicit terminating newline is
inserted. The logical borrow length is the exact frame extent.

Header, 16 bytes:

- Bytes 0..3: ASCII `CCN1`, decoded integer 827212611.
- Bytes 4..7: package count, 1..4096.
- Bytes 8..11: original file count, 1..16384.
- Bytes 12..15: generated file count, 0..1 for this named workload.

Each record has a 12-byte header: tag, package ID, payload byte count, followed
immediately by that many bytes. Tags are 1 unchanged original, 2 replaced
original, 3 generated target replacement. A zero-length payload is legal.

Original records are in contiguous package groups, IDs 1 through the declared
package count without gaps or empty packages. Preserve Gather file order within
a group. A tag-2 record is an original file and contributes to original totals
AND the replaced subset. It must be followed immediately by exactly one tag-3
record with the same package ID. There is at most one replacement in this
profile. Tag 3 cannot occur otherwise. Generated records do not advance the
package counter. No trailer is allowed. Header counts must match observed counts.

### Preserve the baseline domain

`../baseline.py:22-23` admits 4096 packages, 16384 originals, 16 MiB per original
and 256 MiB combined original bytes. Keep all four limits. Generated bytes and
headers are additional; they do not consume an original's file or byte allowance.

This profile follows `native_driver/Main.chibi`'s `Gather`, which calls
`GatherWith` with an empty `Extra`. Thus the generated test dispatcher/entry in
`GatherWith`/`Test.chibi` are NOT this workload. The baseline has exactly two
collection roots, `project` and `core`. Its unique admitted `core:target` package
contains the single `Target.chibi` path recognized by
`package_compiler/Compile.chibi:4313-4330`. Native scalar input substitutes
`TargetPackageText(..., native=1)` at `package_compiler/Scalar.chibi:5493-5494`.
For the supported numeric OS/architecture/pointer-width values, the inspected
current template is 235 bytes: one-digit OS/architecture/native and two-digit
32/64 pointer width. This is source inspection, not execution of that generator.

Therefore allocate a separate **one generated record / 256 generated bytes**
allowance. The 21-byte margin is explicit, not evidence of a general generator
bound. The preparer must reject an unexpected second generated source, a changed
larger generator, duplicate target path, or another collection/test-generation
profile with a clear profile diagnostic. Such support needs its own measured
workload/bounds, not an undocumented larger global frame cap. Original capacity
stays unchanged if generation is absent or present.

Maximum records: 16384 originals + 1 generated = 16385.
Maximum frame bytes: 16 + 12 * 16385 + 268435456 + 256 = **268632348**.
This cap adds every category's independent bound; it subtracts no original
capacity. The frame can represent the full original domain together with its
allowed generated target record. This is not a claim about every native-driver
command or arbitrary external generators.

## Counting and one report

For each payload, physical lines are the count of LF bytes plus one if the
nonempty payload does not end in LF. Empty payloads have zero lines. A nonblank
line contains a byte outside ASCII whitespace HT/LF/VT/FF/CR/space (9..13, 32).
CRLF is one physical line; a bare CR does not delimit a line. Unicode separators
are bytes, not line endings. NUL is an ordinary nonblank byte. Comments count.

The last-byte initial value LF gives the empty-file behavior without a special
empty branch. The final unterminated line uses the same line-has-text state as
an LF-terminated line. All file counters stay in Chibi locals.

`chibi_census_report` takes exactly sixteen i64 arguments in this order:

1. status (0 success)
2. error_offset (0 on success)
3. packages
4. original_files
5. original_bytes
6. original_lines
7. original_nonblank
8. replaced_files
9. replaced_bytes
10. replaced_lines
11. replaced_nonblank
12. generated_files
13. generated_bytes
14. generated_lines
15. generated_nonblank
16. frame_bytes

There is one static and one dynamic report call. On error, arguments 3..15 are
all zero, not partially accumulated counts; arguments 1, 2, 16 identify the
failure and input extent. The host owns the input filename/sidecar and labels
its printed error with that filename and byte offset. The report returns status
unchanged, and `Census` returns that result. A host output/write error is a
separate environment failure, not a successful census.

Status meanings (checked in source order; first encountered error wins):
1 truncated main header; 2 frame extent exceeds profile; 3 bad magic/version;
4 invalid declared counts; 5 truncated record header; 6 unknown record tag;
7 payload exceeds remaining extent; 8 broken replacement pairing;
9 too many generated records; 10 generated byte allowance exceeded;
11 invalid/noncontiguous package ID; 12 too many originals;
13 original per-file limit; 14 combined original-byte limit;
15 duplicate replaced original; 16 missing paired generated record at EOF;
17 package count mismatch; 18 original count mismatch; 19 generated count mismatch.
Header errors use offset 0. Record errors use the record-header offset. Final
count/pairing mismatches use the frame extent. No malformed input calls an assert.

## Smallest feature set justified by this source

The program has two authored functions (`Census`, `ReadU32`) and one foreign
report import. `ReadU32` serves seven real source call sites. It reads four
checked bytes and constructs a u32 value in i64; it neither parses variable-width
numbers nor performs unaligned loads. No structs, mutable arrays, arbitrary
pointers, byte casts, closures, exceptions, allocation or generic framework are
requested. Existing bool/i64 calls, branches, `&&`, `!`, `==`, `>`, addition and
multiplication remain useful.

Proposed additions, with counted source uses in `inventory.json`:

- `BorrowedBytes`: two ordinary parameter annotations, one public entry parameter
  and one private helper parameter. No borrow result, constructor or stored field.
- `byte_length(BorrowedBytes) -> i64`: one intrinsic call, outside both loops.
- `byte_read_checked(BorrowedBytes, i64) -> i64`: five static intrinsic calls,
  four in the reusable header reader and one in the payload loop.
- Existing language `while` syntax: two statements, outer frame and inner byte
  loops. This is bounded-slice admission, not new language syntax.
- i64 subtraction: four source operators for remaining extents/budgets. Define
  wrapping subtraction consistently with current experimental add/multiply;
  this caller proves the operands keep its results nonnegative. Avoid a special
  subtraction helper or unnatural add/negate spelling to save one opcode.

The source is written using existing tokenizer forms, but tokenization/parsing
of this exact source is not yet executed. Reader/producer admission and native
behavior are separately gated. No feature qualifies as implemented merely
because its trial uses were counted. Other consumers must be counted over time;
remove experimental features that fail to earn their upkeep.

### Nominal admission and a single authority

`frontend/typed/Model.chibi` remains the one authority for type kinds, opcodes,
limits and the intrinsic/type descriptors needed by this extension. Extend its
restricted schema/generator deliberately; do not add a second hand-maintained
Rust type/operation or Chibi intrinsic registry. The generated bindings must
carry the same canonical identities, signatures and operand/result shapes.
Rename the generated scalar-only kind if necessary rather than falsely calling
a pointer/length pair a scalar. Append the new kinds and bump the bridge version
with a new reviewed digest. Keep v3's recorded digest and historical receipts.

Seed one approved `BorrowedBytes` nominal in the ordinary retained
`named_binding`/`signature_reader` environment, using `binding.ID` and the normal
catalog representation. Its descriptor owns the nominal identity and the
reader storage/container/flags tuple; the backend must not infer semantics from
that storage tag. Call `reader.Signature` on each real source annotation and
admit only the returned approved nominal with ordinary unmodified shape.
For this bounded proposal, use the ordinary nominal catalog storage kind 15
(struct), container/flags/parameter/collection zero, with identity
`binding.ID("type", "vnext.BorrowedBytes")`; admit that exact nominal, not every
storage-15 value. This is an opaque compiler capability, not a source-declared
two-field struct and not managed storage. The canonical descriptor owns these
facts. Populate the normal merged/type/ID catalog entries the retained reader
actually consults, not merely a separate `native` list it cannot resolve. Honor
reader diagnostics and legitimate nominal-use records. The current empty
catalog and `nominal == 0` / `uses == []` restrictions must be changed explicitly.
A spelling whitelist returning a new type code is not nominal admission.

Resolve intrinsic symbols through the same canonical descriptor/catalog, then
emit `ByteLength` / `ByteReadChecked`, not `DirectCall` foreign calls. Binding or
package shadowing must follow ordinary resolution; a same-spelled unrelated
function/type cannot acquire intrinsic semantics. Test spoofed/unknown nominal
IDs, local shadows, modifiers, containers and constructor attempts. Do not
silently redefine current managed `^T`, views, strings, arrays or `u64` as this
borrow. This proposal is one narrowly admitted foreign-buffer capability, not
a second managed-pointer model or a general user-defined-record feature.

### Borrow and checked-read contract

A borrow is a nonowning immutable `(base pointer, byte length)` pair, valid for
one synchronous invocation and its nested calls. Length is a nonnegative i64.
Its machine pointer has the target pointer width; the first acceptance target
is the existing Linux x86-64 lane. Borrow construction is restricted to the
explicit inbound entry boundary, which expands the logical parameter to
`const uint8_t *base, int64_t length`. Private Chibi calls expand it identically.
There is no C-aggregate ABI assumption and no foreign borrow-return support.

Zero length may use NULL. Positive length requires actual accessible live
storage for the entire declared extent. The host must hold it unchanged and
unmoved until return, including during report printing. No callback may mutate,
free or reenter with a conflicting alias. Neither the nominal type nor an index
check proves that a foreign pointer/length describes a real allocation: that
unsafe C/JIT boundary contract remains explicit. Invalid memory cannot be turned
into a recoverable framing error by checking an integer bound.

`byte_length` returns the exact declared length. `byte_read_checked` returns
0..255 for 0 <= index < length, otherwise -1, in every build mode. The invalid
path must neither compute an out-of-allocation address nor issue a load. Lower
the check to real control flow around the u8 load and zero extension. A select
with a speculative out-of-bounds load is wrong. No trailing padding is required.
Addition/multiplication in `ReadU32` cannot overflow: valid header bytes decode
at most 4294967295. The caller proves every ReadU32 span and payload index before
use, yet the intrinsic's checked semantics remain independently testable.

Borrow aliases and parameter forwarding are permitted inside the active call.
Reject returning a borrow, writing it to a global/retain/heap/aggregate/array,
capturing it, converting it to an integer/managed pointer, pointer arithmetic,
passing it to arbitrary foreign calls, or suspension. Authored borrowed-formal
uses must satisfy this closed nonescape rule transitively. No general lifetime
annotation solver is needed for the two functions. `Census` passes only i64
counts to C. Keep borrowed formals distinct from arbitrary foreign signatures.

### Backend representation and cost

Keep `Value {type, definition}` at eight scalar bytes and `Instruction` at 24.
A borrowed value is one logical ValueID, with its type only in `Value`. Never
serialize a process pointer into the packed module. Entry and call expansion
create machine pointer/length operands at lowering, not additional semantic
source parameters or independently inferred facts.

Keep the existing scalar value map. Store rare lowered pairs in a side vector
keyed by ValueID, e.g. `{id, pointer_value, length_value}`. This caller requires
two logical borrowed definitions (the two entry parameters), and no borrow loop
parameter because input is invariant. At three 32-bit backend handles per row,
that is a proposed 24 payload bytes for two pair rows, subject to size assertions
on the actual backend handle types. Do not widen every scalar map entry into a
pair or tagged largest-variant union. Sorted side rows permit bounded binary
lookup during compilation; there is no runtime side-table lookup per input byte.

Logical versus expanded arity must be distinguished in signatures, arguments,
block parameters and backend admission. `ReadU32` is 2 logical/3 machine arguments;
`Census` is 1 logical/2 machine arguments. The report is 16/16. Keep the logical
32-parameter limit and independently check expanded machine counts. On Linux x86-64 System V the report uses six integer argument registers plus
ten eight-byte stack arguments (80 bytes before call-frame alignment), with one
i64 return and no hidden result pointer. Require position-distinct canaries and
proper stack alignment in both JIT and linked AOT tests. The old
8-argument foreign proof cannot validate the new report or borrowed entry ABI.

## While lowering and verifier change

Collect each while's source write-set once by resolved **binding ID**, not name,
intersecting with bindings visible before the loop. Recursively include nested
writes to those outer IDs and exclude locals declared within the loop. Resolve
assignment targets while making this set; do not infer expression types twice.
For each selected ID take its type from the canonical pre-loop Value row. Create
header parameters for those values, an entry edge carrying the before-values,
then emit condition and body once with header values installed. A backedge
carries body-exit values; the false edge leads to the continuation. Loop locals
end with the body scope. Existing condition/assignment checks still apply.

For this source, the outer loop carries 17 i64 bindings (status, error_at,
packages, the twelve category counters, pending_package, at); the inner loop
carries file_lines, file_nonblank, last_byte, cursor (i64) and line_has_text
(bool). `input`, limits and lengths invariant in each loop get no loop parameter.
No synthetic general SSA construction framework or speculative type pass is
needed. Break/continue and suspension remain unsupported until a real caller
requires their own semantics and tests; this source uses neither.

The current verifier's forward-target check, `DefinedBefore` physical-order
restriction and one-pass u64 dominance are not compatible with a backedge.
Replace the algorithm, not the safety checks:

1. Keep all table ownership, spans, same-function target, argument arity/type,
   single-definition, same-block instruction order and terminator checks.
2. Build predecessor lists and entry reachability for the complete function.
   Reject every unreachable block, including an unreachable cycle, and incoming
   edges to the function entry. Reachability is not `dominators != 0` during a
   single walk.
3. For reachable blocks, initialize entry dominance to entry only and other
   masks to all function blocks. Iterate predecessor intersections plus the
   block's own bit to a fixed point. Use a bounded worklist; monotone bit removal
   proves termination. Check all uses against the converged masks, including
   backedge arguments at their source terminator, and same-block order as before.
   With B <= 128 and E <= 2B, at most B*(B-1) bits can be removed. A deduplicated
   successor worklist therefore performs at most B + 2B*(B-1) = 32640 pops. A
   loose bound charging E predecessor reads and two mask words to every pop is
   16711680 word intersections per function, not a claim about typical cost.
   Record actual pop/intersection counts; do not describe this algorithm as O(B+E).
4. This caller projects **121 blocks** in Census: entry 1 + 36 ifs * 2 +
   22 explicit else arms + 2 whiles * 3 + 10 short-circuit conjunctions * 2.
   ReadU32 projects one. This is an arithmetic projection of specified lowering,
   not emitted counts. A reviewed 128-block/function cap and two u64 words per
   dominance mask would fit; do not change the cap before the cycle algorithm,
   recomputed table/packing bounds and 128/129 admission tests pass. If actual
   emission exceeds the estimate, investigate and update the design first.
5. At 128 blocks, masks occupy 2048 payload bytes per function; predecessor and
   reachability scratch are additional bounded arrays. The fixed-point verifier
   is not advertised as linear. Measure iterations/bitset work on nested loops
   and worst admitted CFGs before widening beyond this experiment.
6. The backend already precreates all blocks/parameters and seals after emission.
   Emit in reverse postorder so a valid block-layout permutation does not make a
   dominating instruction unavailable in its scalar map. This is scheduling,
   not repeated semantic inference. Preserve same-block instruction order.
   Checked-read expansion adds private backend blocks, not typed Model blocks.

The proposal does not widen to 128 merely because source is long. Per-function
counts are in the inventory: ReadU32 has no branch/loop and needs one block;
Census is the single framing/counting state machine. Its additional blocks are:
header validation 21, record validation 60 (including the outer loop), payload
scan/final line 18 (including the inner loop), category commit 5, and final
validation/report 16, plus the entry block. The inventory identifies exact source
line ranges for these projections. The byte scan itself needs
line-ending, nonblank and final-line decisions; record checks enforce distinct
external-input errors. Combining checks would lose precise diagnostics or add
hidden compound control. Splitting into encoded multi-result helpers would add
an artificial representation/ABI just to fit a proof limit. Straightforward
empty-jump threading may reduce else-if merge chains and should be measured at
actual emission. Even hypothetically deleting ALL 22 else-arm overhead blocks
and ALL 20 short-circuit blocks leaves the current structured estimate at 79,
still above 64. This is a conservative illustration, not a lower bound on every
possible rewriting or code generator. Do not add an optimizer solely to preserve
an arbitrary experimental cap. Revisit 128 if the real CFG/count evidence differs.

For unchanged row widths and no new per-module descriptor tables, the proposed
128-block bound implies: 4096 total blocks, 262144 block parameters, 270336
values, 12288 instructions, 8192 edges, 8192 calls and 786432 combined arguments
at the existing module limits. The loose packed ceiling is 1746414 u32 words
plus 8192 i64 literals and 65536 name bytes, or 7116728 payload bytes. These are
checked arithmetic ceilings, not reservation sizes, native record layouts or
measurements. Any schema addition requires recomputing them again. The retained
64KiB source/8192-node/64-binding/32-parameter limits stay; this source is 7982
bytes and has 44 peak bindings, while actual parser-node counts remain unmeasured.

New verifier tests must include zero-trip/many-trip/nested loops, unmodified
bindings, multiple assigned scalar types, branch writes in a loop, two loops
with different local bindings, early return, source rejection for unsupported
break/continue, swapped physical block order, missing/wrong/duplicate backedge
arguments, wrong loop-parameter types, cross-function edges, body-defined values
used on the zero-trip exit, same-block future uses, unreachable self-cycles,
incoming entry edges, and 64/65 plus 128/129 block boundaries. Keep all existing
DAG/mutation tests and source diagnostic spans. Reject illegal escape operations
at source and verifier layers where representable; malformed input is not UB.

## Adoption and matching proof, in order

1. Independently review this caller, format and counts. Run the exact source
   through the retained tokenizer/parser with diagnostics and inventory of actual
   nodes, blocks, values and binding write-sets; no hand-built-IR substitute.
2. Implement/gate the minimal type, intrinsic, subtraction and while changes in
   reviewed steps. Regenerate the versioned bridge from the one Model authority;
   test stale-version/layout rejection, nominal reader behavior, packing, typed
   verification, lowered-pair ownership and the entire retained scalar corpus.
3. Write a simple independent reference oracle over the same frame bytes: decode
   each little-endian header with a standard byte unpacker, check the profile in
   the specified order, and count payload LF plus the final-line rule. For
   nonblank, split only on byte LF, discard only the artificial trailing empty
   segment, and test whether each line contains a byte outside {9,10,11,12,13,32}.
   Do not use Unicode splitlines/strip, the Chibi algorithm or a C census as the
   oracle. Return the identical 16-field tuple, including errors/zeroed counters.
4. Table fixtures: empty and unterminated files, only LF, repeated LF, CRLF,
   whitespace-only lines, VT/FF, bare CR, NUL, all 256 byte values, long lines,
   multi-package frames, absent/present replacement, and every status 1..19.
   Mutate/truncate every header field, reorder package IDs, append trailing junk,
   and test malformed lengths (including 0xffffffff). Boundary controls cover
   4096/4097 packages, 16384/16385 originals, 16 MiB +/- 1, 256 MiB +/- 1 combined
   originals, generated counts 0/1/2 and bytes 256/257, and full original capacity
   PLUS an allowed generated record. Large fixtures are generated for execution,
   not embedded into compiler source. Fuzz frame bytes with minimized replays.
5. Intrinsic controls on real immutable allocations: empty/NULL, index -1, 0,
   last, exactly length, INT64_MIN/MAX; bytes 0/127/128/255; guard-page boundary
   proving no invalid load. Do not pass forged/freed pointers as 'safe rejection'
   tests. Borrow escape/unknown-type tests must reject compilation.
6. Feed the exact original Chibi caller through Produce -> Verify -> Pack into
   eager JIT and linked AOT. Compare all sixteen fields and the returned status
   against the independent oracle for the same bytes. Assert exactly one report
   call, correct register AND stack arguments, no per-byte foreign imports, and
   missing-report-symbol owned failure. Include adversarial distinct values for
   all sixteen ABI positions; all-zero/error or symmetric counters are inadequate.
   Retain loaded report code until all JIT owners are destroyed.
7. Re-gather the actual immutable native_driver closure against recorded HEAD/
   tree, compare every file/package/hash with baseline.py, derive replaced and
   generated records from the actual compile-input generator, and match complete
   original/replaced/generated reports. The historical numbers below are only
   cross-checks, not a fresh closure receipt. Admit the same full original domain.
8. Accept the four current-v3 public native selections separately. Their older
   v2 receipts and the five-stage v3 foreign proof do not accept this extension.
   Record exact source/tool/runtime identities and independent aggregate review
   before any real-tool acceptance claim; publish docs without upgrading status.

Review clarifications for implementation and adoption:

- The four subtractions in this caller are range-safe. Add separate retained-parser
  cases for signed-boundary wrapping subtraction, operand order, and literal-only
  subtraction; verify the same typed operations through JIT and linked AOT. Frame
  validation alone does not prove the new SubI64 semantics.
- The current baseline receipt stores per-file physical_lines and compares the
  complete receipt before execution. CCN1 reports aggregate counters only. The
  first accepted census tool must keep the current per-file Python counts labeled
  as reference work. Before claiming it replaces that path, explicitly choose and
  test a receipt-schema migration; do not silently drop fields or count both paths
  as a single faster implementation. This proposal does not add a per-file API.
- Fresh public replay requires all five existing selections, including foreign.
  Historical four-selection or foreign-only evidence cannot stand in for the full
  current five-case developer replay after a source/tool reconstruction.

Before acceptance, add small deterministic n/4n work checks:

- Use fixed-depth source fixtures with fixed visible-binding counts and 4/16
  disjoint loops. Count write-set assignment-target resolutions and syntax/
  expression visits separately from emission; reject repeated/quadratic walks.
- Use valid one-record frames with 256/1024 payload bytes, and 256/1024 empty-
  record frames. Check exactly P + 16 + 12R checked byte reads and one report,
  where P is payload bytes and R is records. Keep counters test-only, outside
  production per-node mode checks, and use existing test registration rather
  than a new instrumentation framework.
- Record verifier worklist pops/intersections separately on 32/128-block CFG
  families against the documented bounded algorithm. Do not impose or claim
  linear dominance. These counts are acceptance requirements, not results.

Current `compile_both` intentionally performs both JIT and object work. Its cost
is a dual-output functional-proof cost. A future development benchmark must
choose eager JIT OR object-only before backend work; it cannot discard an output
or subtract the other path's elapsed time after compiling both. This proposal
implements no output-mode API. Full compilation timing includes startup through
linked executable/finalized eager JIT and real required work; independent harness
identity checks remain labeled outside timing. Keep O0/O2 and code-quality gates.
