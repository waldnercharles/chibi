# Current language contract, version 1

Source snapshot: engine `62906a504fee6b2e0bd6349a8eeff1450529cd90`,
15 October 2026. Project format **24** and prepared execution format **13**
are different version domains. This document records existing behavior for L00;
it does not choose new syntax or complete L00's cross-backend conformance gate.
The [Stage 0 baseline](../studio-migration-roadmap/baseline/README.md) retains
its original SDK pairs and unresolved health/product gates.

## Status and authority

- **Source-proven (S):** a declaration, call path or checked-in assertion was
  inspected at the pinned commit. This proves what source says, not execution.
- **Implemented, execution unverified here (I):** the implementation and named
  C/pico_unit cases exist. All runtime contracts below have this evidence level;
  no product tests, builds, benchmark, Studio or browser execution ran for this
  documentation slice. A test name is not a pass.
- **Proposed (P):** an unimplemented or unselected extension, explicitly separated
  below. Owner-approved direction still needs implementation and exact-head tests.

“MUST” below specifies the preservation obligation for the documented current
contract, within its stated supported inputs. It is not permission to accept a
new source form, widen a native ABI or treat an untested implementation as sound.
A disagreement between backend implementations remains a conformance defect to
resolve, not a choice of whichever result is convenient.

[conformance.csv](conformance.csv) maps clauses to existing dispatcher
routes and exact C cases, including negative controls and backend limits.
[sources.csv](sources.csv) pins every cited implementation/fixture with Git blob,
size, SHA-256 and immutable URL. [validation.json](validation.json) records only
source/document checks. References use the pinned commit rather than `main`. Route names are arguments
to `python3 tools/test_policy.py tool <name>` with matching built drivers; a map
entry identifies coverage; it does not establish an executed result.

## C01. Lexical and source boundaries (S/I)

A source file contains exactly one behavior, library, system or component root.
Executable analysis accepts the first three; component declarations use their
separate component reader. Declarative project/scene/etc. data remains KDL;
RML/RCSS are separate UI formats. Empty text is not a valid empty program.

Later addition: the explicit SDK package-analysis entry points accept sibling
`package` documents with shared functions, constants and types. This does not
change the pinned single-source contract above. The
[language guide](../code-language.md#packages-and-visibility) introduces package
syntax and visibility. The active implementation checkpoint is
[M3](../../PLAN.md#m3-make-packages-executable).

Identifiers are ASCII `[a-zA-Z_][a-zA-Z0-9_]*`; quoted names use string tokens.
Numbers are decimal with optional fractional/exponent parts or hexadecimal
integers. A leading sign is an operator. Strings use JSON decoding in semantic
analysis; invalid escapes and embedded NUL are rejected. Lexical acceptance
alone does not establish a valid runtime string or numeric value.

Whitespace, `//` and non-nesting `/* */` comments separate tokens. A semicolon,
closing brace/end of file, or an eligible newline terminates a statement. The
external scanner suppresses newline termination before continuation punctuation;
comments containing newlines participate without losing the comment token.
Same-line statements need explicit separation. Binary operators associate left,
with precedence from `or/||`, `and/&&`, bitwise `|`, `^`, `&`, equality,
comparison, shifts, sum, product, unary to member access. Reserved versus
contextual words are the explicit grammar lists, not an inferred English rule.

Sources: [grammar][grammar], [terminator scanner][scanner],
[string/name decoding][context].

## C02. Names, scope and persistent storage (S/I)

A bare value name resolves from the nearest lexical scope outward; constants
cannot be assigned. `::` declares constants, named functions and unions;
`:=` declares mutable storage. Constants reject runtime dependencies and calls,
including a call merely marked pure. Named `fn` is currently optional.

Root value declarations are persistent; `state` is currently optional there.
Inside a callable, an ordinary declaration is local while explicit `state`
selects persistent storage. System `shared` state is registration-owned, shared
across matching instances, and cannot hold a task. `shared` outside systems is
rejected. Behavior `self` is the owner entity. Current explicit persistent
lookup is `state.name` (including quoted names), which also finds shared state.
Nested named functions cannot implicitly capture an enclosing local: it must
be passed as a parameter. Qualified authored calls use the project catalog.
This snapshot does not promise the unresolved duplicate-export fix or new imports.

Symbol IDs include source identity, lexical scope ordinal, name and callable/
result domain. Source occurrence IDs use the source document's key, the record
kind and the record's range counted in bytes that are not whitespace (a
symbol's is its declaration), so every compiler of the same source gives the
same ones (`script_occurrence`). Whitespace edits preserve these identities; arbitrary structural edits or renames
are not guaranteed to preserve state. The minimizer checks equivalence before
accepting a simplification. Storage identity is not display spelling alone.

The approved future rule is bare persistent names, with `self.count` selecting
persistent `count` when a local/parameter shadows it. Removing redundant
root `state` through semantic migration is approved; callable `state` and
meaningful `shared` remain. That approval is **not implementation evidence at
this snapshot**. Library receivers, broader shared/callable precedence,
collision precedence and named-`fn` rejection remain unresolved. A guarded
additive implementation must preserve existing `self.Transform`/`self.Weapon`
component access and diagnose or gate ambiguous persistent/component matches.
The current minimizer can remove redundant `state.name` qualification, but
does not remove a root declaration's `state` token. That requires a separate
semantically checked rewrite; the whitespace formatter must not do it.

Sources: [scope/storage lookup][context], [member lookup][calls],
[storage declarations][declarations], [record identity][identity],
[exact decision scope](../studio-migration-roadmap/decisions.md).

## C03. Values, types and collections (S/I)

`number` and `double` have F64 storage; `float` has F32 storage. `int`, `int64`
and the other declared scalar widths remain distinct. Entities/nominal handles
and task IDs use 64-bit integer storage, never a `number` surrogate. Without an
expected numeric type, integer literal spellings choose `int`, then `int64` or
`uint64` as needed; decimal points and exponents choose `number`. An inferred
mutable declaration keeps its initializer's type. Expected types and typed
operands supply arithmetic context. Empty arrays and nominal values need
adequate type context. Task, handle and collection state can start empty; other missing
required defaults are diagnosed.

Arrays, `set<T>` and current `map<T>` are homogeneous value containers. This
one-type map is not a selected `dict<K,V>` design. Managed values crossing owning
boundaries MUST snapshot their payloads, including registered nested struct
fields and nominal names. Plain copying a host header is not that guarantee.
Collection indexing/lookup retains ordered items and first-match equality;
internal hash indexes do not change iteration order. No contiguous packed
AoS/SoA ABI or automatic storage layout is promised.

Reflected structs are available; new authored record declarations are not.
Named tagged/literal/type unions own immutable payload snapshots. `is` narrows
only where the proof holds; writes/effects can invalidate it. `as T` extracts
`T?`, not a numeric conversion. Optional presence preserves zero, false and
empty text as present. Finite union switches require all alternatives or a
default, and successful result paths must initialize their results. Recursive
owned union payloads and managed union ECS fields are rejected.

Sources: [type identities and assignability][catalog], [value storage][values],
[defaults][context], [snapshots][arrays], [union ownership][union],
[union analysis][union-analysis], [collection indexing][index].

## C04. Numerics, indexing and order (S/I)

- Typed integer literals MUST preserve exact bits within their declared range;
  overflowing literals are errors. A 64-bit ID must not round-trip through F64.
  This does not imply that every syntactically named scalar supports every cast
  or arithmetic operation: lowering and verifier support are authoritative.
- Supported `int`/`int64` add/subtract/multiply/negation use width-wrapping bits.
  Integer division/remainder reject zero and signed minimum divided by `-1`;
  otherwise division truncates toward zero. Bitwise operations preserve their
  declared width; shift counts use the low log2(width) bits, signed right shift
  sign-extends, unsigned right shift zero-fills, and left shift wraps.
- F32 operations retain their F32 rounding; F64 retains F64 rounding. Min/max
  use strict comparison and select the right operand on a tie or unordered
  comparison, including NaN/signed-zero effects. Optimizations MUST preserve
  these observations. Transcendental results are not a cross-platform bitwise
  promise; sine/cosine use the shared approximation, other operations can call
  platform math implementations.
- Supported floating-to-integer casts truncate, clamp at the destination bounds,
  and map NaN to zero. The supported conversion matrix is narrower than “all
  numbers convert to all numbers.” No silent uint64-to-F64 precision guarantee
  follows from numeric assignability.
- Source array access emits lower/upper bounds assertions before item access.
  Floating array indices/range bounds pass through the current int conversion
  (fraction truncated); this is not a newly selected index policy. Invalid
  references after collection replacement fail rather than reusing stale paths.
- Ordinary binary expressions lower left then right; `and/&&` and `or/||`
  short-circuit. A local initializer evaluates once at that statement. A switch
  evaluates its subject once and does not fall through. Ranges are inclusive.
  Native calls can have capability-specific input demand/order: the state-action
  fixture deliberately expects Multi Gate input order 3, 2, 1. Do not impose a
  universal textual argument-order claim over that existing contract.

Sources: [scalar casts/bitwise][scalar], [VM arithmetic][machine],
[native integer lowering][integer-jit], [source lowering][lower],
[shared math operation list][instructions]. C04's fixture map includes exact
integer literals, float conversion, NaN/signed zero and negative failures; it
is not exhaustive proof of all width/operator/backend combinations. Readable
existing witnesses (assertion source, not freshly executed results):

- `behavior Limits { sample: int8 = 128; }` is rejected, while the same
  declaration using `int64 = 9223372036854775807` is accepted by
  `language_numeric_literal_storage_limits` (semantic-only).
- `program_integer_and_nominal_enum_literals_preserve_exact_bits` stores
  `9007199254740993` in `uint64` without an F64 round trip on its two backend paths.
- `program_array_literals_are_fresh_copies` sets the first returned array
  element to `99`; a new call still returns original first element `3`. It loops
  bytecode and `TEST_COMPILED_BACKEND`, SLJIT natively or Wasm under Emscripten.

The exact files/lines and test routes for these witnesses are in the CSV.

## C05. Ownership, references and automatic lifetime (S/I)

Ordinary authored users do not allocate arenas, choose allocators or free values.
These are runtime implementation details. Owning argument/result/state/suspension
boundaries retain snapshots automatically. An explicit `ref` is an alias, not a
by-value copy. References to ECS storage are checked/reacquired through runtime
identity/layout information; a component pointer must not be retained over a
yield or structural mutation.

Existing task ref arguments may share a local through a box. The caller and
child observe the same local while attached; when the declaring frame/scope
retires, the box owns a snapshot and lives until its holders release it.
Replacing a detached managed root must keep earlier independent snapshots valid,
reacquire descendant paths, fail invalid paths atomically, and release retired
payloads when no live roots need them. This is existing explicit-reference
semantics, **not** an inferred lambda capture rule.

Read-only array borrowing is an internal optimization. It requires verified
synchronous nonescape/no-mutation/no-identity-observation conditions plus runtime
alias/header guards. Unsupported, recursive, opaque, inspected or suspended paths
keep owning snapshots. Failure semantics MUST remain those of the owning path.
Purity alone does not prove borrow safety; generated-C helper boundaries can
conservatively keep snapshots. Retained-capacity bounds are not limits on valid
input size and are not a measured speedup claim.

Sources: [call ownership][call-runtime], [task boxes and collection][tasks],
[checked references][intrinsics], [snapshot storage][arrays],
[borrow proof][borrow], [memory accounting contract][module].

## C06. Execution, events and tasks (S/I)

Analysis lowers directly to verified immutable modules; presentation graphs do
not supply executable state. Live programs, instances and backend code have
separate ownership. Bytecode is the reference execution route; native SLJIT and
actual Wasm are distinct compiled routes. Native invocation of a Wasm-named
selector only checks that Wasm is unavailable there. Inspection may run a
canonical path and must not be counted as compiled normal-path proof.

A synchronous authored call finishes before its caller continues. A function
that can suspend starts a task and runs to its first suspension before the
caller continues. Direct await of an authored call returns its successful result;
await of a task handle returns successful value/tuple or distinct `Cancelled`.
A native awaited call selects its supported completion outcome; it is not a
blanket threading primitive. Event payloads use registered schemas, with
read-only values unless the signature explicitly supplies references.

`yield` resumes on the next update. Cancellation stops the task and its owned
children, waking independent awaiters with `Cancelled`; previous effects are not
rolled back. A cancellation deadline is original start time plus duration, using
the game clock; negative/NaN durations are zero, positive infinity has no finite
deadline, and the earliest scheduled deadline wins. Completion preserves success.
Dropping the last handle does not cancel running work. Completed results remain
while reachable by owner-local handles/waiters; each waiter receives an owned
snapshot. Owner removal cancels work. A handle copied to another owner does not
grant access to the original task. Slot reuse must not revive stale handles.

Source/budget failures are surfaced with retained source/owner diagnostics;
ordinary prior writes/effects are not an implicit transaction rollback.

Sources: [backend selection][backend], [task runtime][tasks],
[execution status][status], [task semantics/lowering][lower],
[live program and failure contract][module].

## C07. ECS queries, effects and reductions (S/I)

Required/optional/excluded component bindings and relationship/generator sources
are resolved against the installed schema. Optional access requires a presence
proof; suspension invalidates the proof. Tuple membership owns per-row state;
leaving membership or changing entity generation retires that instance and its
work. Shared system state is separate and survives ordinary membership churn.
Query admission/value filters preserve their prepared membership and
short-circuit/error order. Predicates must have verified allowed read effects,
bound query variables and no hidden state/effect dependency after linking.

Effects are derived from finalized instructions, linked callees and installed
host access, not trusted merely because source says `pure`. Unknown effects are
conservative and exclude parallel execution. Structural operations must respect
runtime iteration/command boundaries. Source component paths do not guarantee
live component presence. Checked scalar reads exist in this snapshot; the
separately owned checked-write candidate is not a current-contract claim here.

Reduction producers cannot ordinarily read/write the reduced component through
helpers, bindings or filters; membership tests remain allowed. Contributions
publish after the system batch before dependent query preparation. Ordered
reductions retain system/row order, destination-width wrapping, per-update range
clamping and comparison-select min/max semantics. A failed dispatch discards its
contributions and later peers; earlier successful systems remain published.
Debug pause retains unfinished work; replacement/reset cancels that log.

Eligible reduction rows **can run in parallel** with private contributions and
ordered merge. The actual gate also requires enough rows/workers, streaming
execution, no ordinary writes, and no observer/inspection/profiling exclusion.
Otherwise execution falls back to serial. `reduce unordered ... += ...` explicitly
allows regrouping, changing floating rounding/NaNs/signed zero and write revision
counts. It requires an unbounded field and cannot mix ordered/unordered reduction
modes on the same component. Neither path promises a speedup.

Sources: [preflight][preflight], [effect derivation][effects],
[query/reference lowering][lower], [system dispatch gate][source-runtime],
[row workers and ordered merge][program], [scheduler][scheduler].

## C08. Native boundary and prepared compatibility (S/I)

The current native boundary is registered typed capability/service metadata.
Host calls borrow arguments for the call and must not retain them, reenter graphs
or invalidate component/behavior storage. Successful fixed-result calls write
all payloads while preserving supplied headers/backing. Owned-value callbacks
construct complete results in caller-provided runtime storage. Error text must
outlive the activation. Synchronous commands own retained arguments before
return; async begin transfers its host request reference only on success.
Request detachment makes late completion fail without touching the old owner;
the host still releases its reference exactly once. These serial-scheduler
interfaces are not an arbitrary thread-safe callback or C-function-pointer ABI.

Prepared artifacts store canonical definitions, stable capability/type/event
identities and immutable dependency fingerprints, not process pointers or JIT
code. The reader rejects unknown version, target ABI/instruction schema mismatch,
missing identity, signature/layout mismatch and malformed/budget-exceeding input
before publication. Backend code is rebuilt; effects/borrow proofs are rederived.
Version 13's ABI includes instruction names and ordinals. A semantic/payload
change can still require a version change even when those names are unchanged.
This is target compatibility, not a universal cross-pointer-width binary format.

Sources: [host callbacks][host], [request ownership][request],
[prepared public contract][prepared], [prepared decoder][prepared-reader],
[instruction schema][instructions]. No broad C facade, registry rewrite or LLVM
backend is introduced by this document.

## C09. Authored publication and project migration (S/I)

The real preview caller stages a complete valid working collection and publishes
only after presentations, dependencies, event/type compatibility and runtime
programs are prepared. A failure leaves the applied generations intact. Draft,
applied and saved source remain distinct.

`preview_sources_stage` sets `restart` only for the explicit `restart_path`.
For nonrestart replacement, `matching_state` matches stable state ID, sharedness,
scalar storage, container and nominal name. Matching values are copied; new or
nonmatching values use new defaults and removed values disappear. This matcher
does **not** itself compare reflected layout hashes. Schema preflight/linking is
separate; do not claim arbitrary in-place reflected-layout migration is safe.
Compatible imported state is also considered. Query-managed rows are preserved
only when generator shape matches. Publication replaces the program and retires
old activations/tasks/requests; it does not wait for suspended tasks to finish.
An explicit restart resets state/defaults and attachment Begin intent. Ordinary
source publication does not unconditionally reset all system/shared state.

Native application DLL replacement/watching is already removed. Native changes
require rebuild/restart; `.chibi` publication, RML/RCSS updates and workspace
checkpoint recovery remain different mechanisms and MUST be preserved.

`CHIBI_PROJECT_VERSION` is 24; the migrator's version-23 step rewrites old
`function`/`match` source to current declarations/switch. A future project-version
bump requires a real affected repository/Studio/Celeste project that would load
incorrectly and a migration that rewrites it. Additive grammar or documentation
alone does not qualify. The approved root-state migration is not implemented
by this docs slice. Project and prepared versions MUST not be substituted for
each other or for graph document versions.

## C10. Tooling and remaining acceptance (S/I/P)

The whitespace formatter and semantic minimizer are separate SDK operations.
The controller's saved-source formatting path can minimize then format; this
does not mean every formatter entry point simplifies semantics. Minimization
reanalyzes candidate rewrites, preserving evaluated order, binding identity and
comments; invalid input stays unchanged by minimization. Configurable formatter
SDK defaults/options/maps exist and emit LF; complete Studio/controller setting
integration, alternate line endings and RML/RCSS formatting are not established.
Metadata is bound to exact source bytes; stale metadata is ignored. Navigation,
rename and source edits use shared resolved identities; invalid drafts cannot
replace applied executable state. Diagnostic/cost summaries are static evidence,
not timings or proof that a conditional operation executes.

Sources: [formatter interface][formatter], [minimizer][minimizer],
[controller formatting caller][controller], [metadata][metadata],
[navigation contract](../authoring-navigation.md).

Remaining L00 gates:

1. Independently review this source contract and reconcile contradictions with
   actual callers. The conformance CSV is a selected map, not an exhaustive
   grammar/type/operator or function-body inventory.
2. Execute the affected existing C/pico routes on exact clean candidates,
   with actual bytecode/SLJIT and actual Node/Wasm identified. Source metadata
   checks do not establish runtime coverage.
   Missing affected-contract coverage remains a gate, never a successful skip.
3. Fill negative/cross-backend gaps, especially complete conversion/overflow/order
   matrices, structural invalidation, layout-changing publication and owner
   lifecycle. Generated-C, browser UI, native platform, SDK consumer, pixel and
   retention/performance acceptance are distinct from these language fixtures.
4. Resolve [capture lifetime/signature choices](capture-lifetime-proposal.md) and
   the remaining [owner decisions](../studio-migration-roadmap/decisions.md)
   before implementing their visible semantics. Records/storage/layout and the
   RML/RCSS engine are not selected. State/self approval stays scoped.
5. Stage 0 executable SDK pairs/health, Stage 1 concrete language consumers and
   Stage 2 owner-bound service/FFI failure/cancel/reload evidence remain open.
   This slice cannot open broad Studio panel translation or close L00 as a whole.
