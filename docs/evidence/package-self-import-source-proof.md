# Additive source proof: ordinary Odin directory self-import

Date: 2026-10-17 UTC. Official pin: `151d53f44e6eed745b067441a6262fb19c728587`. This preserves all prior packet files unchanged. It closes the source-trace question for an existing ordinary directory package, not Odin single-file mode. No Odin compiler or Chibi runtime was built or executed.

## Complete ordinary-directory path

1. The import parser creates an import declaration; its special `"."` rejection is commented out. [parser.cpp 5825–5864](https://github.com/odin-lang/Odin/blob/151d53f44e6eed745b067441a6262fb19c728587/src/parser.cpp#L5825-L5864)
2. The initial directory is normalized by `path_to_full_path` before registration. [parser.cpp 7791–7835](https://github.com/odin-lang/Odin/blob/151d53f44e6eed745b067441a6262fb19c728587/src/parser.cpp#L7791-L7835), [path.cpp 154–168](https://github.com/odin-lang/Odin/blob/151d53f44e6eed745b067441a6262fb19c728587/src/path.cpp#L154-L168). Its helper uses Unix `realpath`, resolving existing symlinks, or Windows `GetFullPathNameW`, a different platform normalization primitive. [gb.h 5681–5759](https://github.com/odin-lang/Odin/blob/151d53f44e6eed745b067441a6262fb19c728587/src/gb/gb.h#L5681-L5759)
3. The file's import path is resolved relative to the declaring file's directory (or explicit collection), then stored as `ImportDecl.fullpath`. [parser.cpp 6797–6956](https://github.com/odin-lang/Odin/blob/151d53f44e6eed745b067441a6262fb19c728587/src/parser.cpp#L6797-L6956), [build_settings.cpp 1541–1563](https://github.com/odin-lang/Odin/blob/151d53f44e6eed745b067441a6262fb19c728587/src/build_settings.cpp#L1541-L1563). The Unix branch again uses `realpath`; Windows uses `GetFullPathNameW` and normalizes separators. [build_settings.cpp 1456–1534](https://github.com/odin-lang/Odin/blob/151d53f44e6eed745b067441a6262fb19c728587/src/build_settings.cpp#L1456-L1534)
4. The imported-path set detects that canonical path before allocating another package. [parser.cpp 6558–6574](https://github.com/odin-lang/Odin/blob/151d53f44e6eed745b067441a6262fb19c728587/src/parser.cpp#L6558-L6574). Thus ordinary `import self "."` reaches the existing package rather than producing a duplicate header/name universe.
5. Dependency construction points the import back to that same package and records a self predecessor/successor. [checker.cpp 5967–5996](https://github.com/odin-lang/Odin/blob/151d53f44e6eed745b067441a6262fb19c728587/src/checker.cpp#L5967-L5996). Its path search returns a one-item self path, while the import-cycle diagnostic requires more than one item. [checker.cpp 6068–6114](https://github.com/odin-lang/Odin/blob/151d53f44e6eed745b067441a6262fb19c728587/src/checker.cpp#L6068-L6114), [checker.cpp 6584–6626](https://github.com/odin-lang/Odin/blob/151d53f44e6eed745b067441a6262fb19c728587/src/checker.cpp#L6584-L6626).
6. Updating the popped self predecessor does not requeue it: pop leaves the node's index at the new count; heap fix/shift-up exclude that index from comparisons. [priority_queue.cpp 9–67](https://github.com/odin-lang/Odin/blob/151d53f44e6eed745b067441a6262fb19c728587/src/priority_queue.cpp#L9-L67), [checker.cpp 193–199](https://github.com/odin-lang/Odin/blob/151d53f44e6eed745b067441a6262fb19c728587/src/checker.cpp#L193-L199).
7. Normal import binding looks up that package scope and adds its alias only to the importing file; the default alias uses the resolved directory basename, and a deliberate `_` import is force-used without scope insertion. [checker.cpp 5921–5958](https://github.com/odin-lang/Odin/blob/151d53f44e6eed745b067441a6262fb19c728587/src/checker.cpp#L5921-L5958), [checker.cpp 6147–6224](https://github.com/odin-lang/Odin/blob/151d53f44e6eed745b067441a6262fb19c728587/src/checker.cpp#L6147-L6224), [checker.cpp 2287–2298](https://github.com/odin-lang/Odin/blob/151d53f44e6eed745b067441a6262fb19c728587/src/checker.cpp#L2287-L2298).
8. Selector resolution treats the self alias like an ordinary import: it checks the package's declared/exported member, with no same-package prohibition. A self alias does not bypass private export checks. [check_expr.cpp 6274–6286](https://github.com/odin-lang/Odin/blob/151d53f44e6eed745b067441a6262fb19c728587/src/check_expr.cpp#L6274-L6286), [check_expr.cpp 6455–6496](https://github.com/odin-lang/Odin/blob/151d53f44e6eed745b067441a6262fb19c728587/src/check_expr.cpp#L6455-L6496), [entity.cpp 434–452](https://github.com/odin-lang/Odin/blob/151d53f44e6eed745b067441a6262fb19c728587/src/entity.cpp#L434-L452).

Conclusion: this source path admits an ordinary directory package importing itself and binds the alias to the same scope. Invalid aliases, private selection, duplicate bindings and other normal errors can still reject a particular program. This is not an executed compiler acceptance witness.

## Explicit scope limits and mixed-self qualification

Single-file initial-package mode keys its package by the file path and is outside the conclusion above. [parser.cpp 6576–6593](https://github.com/odin-lang/Odin/blob/151d53f44e6eed745b067441a6262fb19c728587/src/parser.cpp#L6576-L6593). Chibi's future single-file helper must not pretend to have complete directory membership.

The pinned queue includes diagonal/self edges in dependency counts and breaks equal counts by full path. [checker.cpp 177–190](https://github.com/odin-lang/Odin/blob/151d53f44e6eed745b067441a6262fb19c728587/src/checker.cpp#L177-L190), [checker.cpp 6048–6057](https://github.com/odin-lang/Odin/blob/151d53f44e6eed745b067441a6262fb19c728587/src/checker.cpp#L6048-L6057). A concrete source-level order trace is `/root/a` importing `/root/z`, while `/root/z` imports itself. Both have count one; the comparator selects `a`. No return path reaches `a`, so it emits before `z`; `z`'s self path then has length one. The recorded package order in that routine is `a` before its dependency `z`.

A second source-level routine trace has A and B each list their self import first, then import each other. The first-return path search can report only each one-item self path at the corresponding pop. This is not an executed whole-compiler cycle-acceptance witness, and no claim is made that later validation cannot reject the complete program.

The governing approved contract is deterministic dependency-correct initialization and rejection of genuine multi-package cycles, including unused cycles. Odin parity here means the specified package syntax/semantics, not reproducing incidental queue behavior. Accordingly the private Chibi draft retains self-import identity/bindings/edges, orders only inter-package constraints, and rejects genuine larger cycles. The mixed graphs are finite regression fixtures for that approved contract. The source observations qualify literal implementation-parity claims; they introduce no new user-visible restriction or design blocker. Frontend, visibility and runtime activation still require their separate integration and validation gates.
