Node design study

References from other node editors, then proposals for Studio's graph nodes, each against today's version. Proposals are mockups at 100% zoom with the canvas's metrics.

References

1 · Bound values without “Self”

Today

Proposed recommended

A component binding always reads the owner, so “Self” carries nothing. Unreal's member getters and component references drop it too; “self” and Unity's “This” appear only as the default of a call's Target pin, where another object could be wired. An icon tells a component from a variable, event value or local, and names are humanized. Hover shows the expression path, Self.Aim.manual.

2 · Flow pins in the title row

Today (Unreal)

Proposed (Unity Visual Scripting)

The unlabeled Exec and Then pins move onto the title bar, saving a row on every step node. Named branches like True and False keep their rows.

3 · Compact operators and getters

Today

Proposed (Unreal compact nodes, variable getters)

Operators become symbol badges and one-output reads become pills. The graph reads as a formula, and the steps that matter stand out.

4 · Expressions as code

Today

Proposed

The expression is the node's content, so it shows in full and highlighted instead of truncated in the title.

5 · Header style

Full color (Blender, Unreal; today)

Neutral with a category stripe (Rivet, n8n)

This is closer to Studio's calm panels. Category shows in the stripe and icon, so selection and run state get more contrast.

6 · Container sockets

Today

Proposed (Blender fields, Unreal arrays)

Arrays and sets get square sockets, so a many-valued pin is visible before hovering.

7 · Light theme

Dark

Light (Blender's light theme)

Today the graph stays dark in the light theme, as the Scene viewport does.
