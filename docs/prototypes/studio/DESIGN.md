# Studio: design direction for the RmlUi editor

This study refines the approved **A · Studio** layout from the `cwaldner/editor-design-prototype` branch. It uses real Neon Swarm content: `fixture.js` is a snapshot of `projects/arena2d` (the Sandbox scene, 24 prototypes and 14 behaviors). The [component kit](kit.html) is the specification for the RmlUi port. Each control there lists its behavior contract, states and keys.

## Visual language

Studio is a daily desktop authoring tool. Its design dials are **variance 2, motion 2, density 6**. The foundation is the existing RmlUi kit and authored Studio assets. Marketing layouts, cinematic scroll effects, decorative glass and randomized compositions do not fit this workspace.

- **Typography:** embedded Geist at 13 dp with 18 dp leading, 500-weight control labels and 600-weight titles. GeistNumeric supplies tabular numerals. JetBrains Mono is reserved for source, paths and expressions. The font and its measurements are identical on desktop and web.
- **Color:** the default light and dark palettes use cool neutrals with blue for selection, focus and primary actions. Named palettes keep their base, text and accent colors while sharing the same component roles. Status, overrides, axes, syntax and graph categories use semantic colors where those colors carry meaning. Helper text uses the same readable contrast floor as secondary labels.
- **Structure:** quiet chrome, clear content, solid fields and overlays. A global toolbar sits above a document tab row, with an underline identifying the active document. Secondary toolbar labels collapse to icons at narrow widths; their tooltips keep names and shortcuts available. Separate areas with a soft line, and use a bordered group only for related editable fields. Overlays (menus, popovers, the command palette, toasts and dialogs) float on the `--shadow-overlay` elevation, a soft drop with a tight contact shadow, and tooltips on the lighter `--shadow-tooltip`; areas stay flat. Controls have 4 dp corners; panels and overlays have 6 dp corners, and a rounded area clips its content, the scene view included, at its corners.
- **Density:** compact controls and virtualized rows are 26 dp; comfortable controls and rows are 30 dp. Headers and the document tab row are 32/36 dp, the toolbar is 40/44 dp and the status bar is 28/30 dp. The defaults live in `theme/roles.rcss`; font preferences scale the shell metrics proportionally, and native lists read `--row` through `kit_metric`, and authored Lists through `ui_list_window`, so changing an authored metric also changes their virtualization geometry. The graph retains its fixed 22 dp socket pitch in its own context.
- **Feedback:** pointer press is immediate. Focus is visible, text and icons align at the control center, and selected controls share a soft accent fill. Search appears immediately. Occasional popovers fade for 140 ms in and 100 ms out without shifting their anchor. Dragged controls track the pointer directly and hand release velocity to an existing spring. Reduce Motion makes changes immediate.
- **Ownership:** RML owns component anatomy, RCSS owns visual choices and layout, and authored behaviors own local interaction that the behavior system can express. C owns authoring data, reflection, virtualized native content and transport glue. New UI must reuse an authored component or a kit primitive before introducing a new presentation path.

| Before | After | Why |
| --- | --- | --- |
| 12 dp text, 22 dp controls, a 30 dp top bar | 13 dp text, 26 dp controls, a 40 dp top bar | Gives labels, icons and controls enough room at normal display scale. |
| Helper text dimmed by mixing it into the background | Secondary and helper labels share readable color roles | Small type needs contrast to remain useful. |
| Native lists repeat density numbers in C | List pitch comes from authored RCSS | The rendered row and the scroll model agree when density changes. |
| Browser collaboration form covers the workspace | Collaboration opens on demand in an authored Studio dialog | Preserves workspace space and uses the same controls, focus and theme. |
| Search shifts while opening | Search appears immediately | Frequent keyboard actions should respond at once. |

### Theme presets

Settings → Appearance → Theme uses the authored Select component. System, Dark and Light remain available. Named choices include Dracula; Solarized Light and Dark; Tokyo Night, Storm and Day; Catppuccin Latte, Frappé, Macchiato and Mocha; Rosé Pine, Moon and Dawn; and Gruvbox Light and Dark.

`theme/presets.rcss` owns their palette values. A single preference applies to the shell, mounted components and the graph's separate rendering context, and persists with the other editor preferences. The standalone StudioShell RML binds the same classes when previewed as an authored document. Switching removes the previous preset class and suppresses transitions during the palette change. Fonts, density, layout and control behavior are shared across presets.

Palette sources are [Dracula](https://draculatheme.com/contribute), [Solarized](https://ethanschoonover.com/solarized/), [Tokyo Night](https://github.com/folke/tokyonight.nvim), [Catppuccin](https://catppuccin.com/palette/), [Rosé Pine](https://rosepinetheme.com/palette/) and [Gruvbox](https://github.com/morhetz/gruvbox). Secondary UI text and status colors are adapted where needed to keep small labels legible on control and overlay surfaces.

## Layout model

The workspace is a split tree of areas. A leaf holds an editor type and that editor's view state; a split holds an axis and a ratio. Drawers are a collapsible leaf at the bottom of the main column. Presets swap the tree without touching documents, selection, history or playback. The hovered area receives editor shortcuts; <kbd>Ctrl Space</kbd> maximizes it. This replaces the `DockBuilder` layout and the `[Chibi][Workspace]` dock IDs. Persisted state becomes the serialized tree.

Two layout modes ship, selected from the top bar or View ▸ Layout Mode. Vertical Split stacks Scene over Behavior. Horizontal Split sets the Canvas beside the Text Editor, with Hierarchy over Details on the right. Each remembers its editors, splits, drawer and side pane. Opening a source file or changing tabs keeps the selected mode. Reset Layout resets the active mode only. The top bar's side-pane toggle and View ▸ Side Pane collapse the right column at its last width, and showing one of its editors opens it again. The modes are fixed; there is no layout editor.

## Interaction rules

- Keys act on the area under the pointer (Blender), Undo, Redo and Save included; a menu acts on the area clicked last. [Studio keys](../../studio-keys.md) lists every binding, and Help ▸ Keyboard Shortcuts (<kbd>⌘/</kbd>) shows them in Studio, searchable and grouped by area. Global keys: <kbd>⌘K</kbd> or <kbd>⌘P</kbd> Search, <kbd>⌘S</kbd>, <kbd>⌘Z</kbd>, <kbd>⌘F</kbd> the area's find or filter, <kbd>⌘=</kbd> <kbd>⌘-</kbd> <kbd>⌘0</kbd> UI Scale, <kbd>Space</kbd> play or pause, <kbd>⇧F5</kbd> stop, <kbd>⌥⌘-</kbd> <kbd>⌥⌘=</kbd> <kbd>⌥⌘0</kbd> playback speed, and <kbd>F5</kbd> <kbd>F10</kbd> <kbd>F11</kbd> while paused at a breakpoint. Over the Scene and Outliner, commands act on the whole selection: <kbd>⇧D</kbd> or <kbd>⌘D</kbd> duplicates, <kbd>X</kbd>, <kbd>Delete</kbd> or <kbd>Backspace</kbd> deletes, <kbd>⌘C</kbd>, <kbd>⌘X</kbd> and <kbd>⌘V</kbd> copy, cut and paste objects, <kbd>F</kbd> frames, <kbd>⌘A</kbd> selects all and <kbd>Esc</kbd> deselects; <kbd>F2</kbd> renames the active object and <kbd>Home</kbd> frames everything in the Scene.
- A focused text field keeps its keys, but Studio's other ⌘ chords still run, as in VS Code. A key that closes a field, popup or dialog does nothing else. While a game has the keyboard, Studio keeps ⌘ chords and the function keys.
- One modifier rule for numbers: <kbd>Alt</kbd> for fine steps, <kbd>Shift</kbd> for coarse steps, <kbd>Ctrl</kbd> to snap. This is Base UI's rule; Blender uses Shift for precision, and we accept that difference for consistency with keyboard stepping.
- Every gesture commits once: a scrub, a picker session or a drag is one undo step. Live updates never write history.
- While the scene runs, playing or paused, Properties shows live values and edits them, as Unity's Play Mode and Godot's remote inspector do: a field of the selected object, placed or spawned, writes the running world on its next frame, with the controls edit mode uses and Reset to Prototype, and keeps its own value while a scrub or typed entry is in progress. Dragging an object in the paused Scene moves it in the running world. Live edits never mark the scene unsaved or write history; Stop restores the authored scene. The Properties header takes a primary wash and a Live badge ("Changes made while playing revert when you stop").
- Keep Changes (<kbd>K</kbd> over Properties or the Scene, the header's Keep, Object › Keep Changes, the Outliner row menu; Unreal's Keep Simulation Changes) records the selected placed object's values that differ from its authored state, what the game changed too, such as its position or facing. A component panel's menu keeps that component's values alone. A toast reports the count with Undo. The running world holds the scene until Stop, so Stop applies the kept values as one Undo step, with a second toast offering Undo; a later Keep decides the values it covers.
- Structure stays read-only while the scene runs, each control disabled with a tip that says to stop: renaming, attaching and detaching behaviors, the Scene tab's settings, and prototypes, whose edits would respawn every instance. A prototype's Properties shows a Read-only badge instead of Live; adding and removing its components waits for Stop.
- Motion is restrained: immediate press feedback, popovers 140 ms in and 100 ms out, drawers 200 ms in and 100 ms out. Search and keyboard-driven changes are instant, and Reduce Motion removes transitions.
- Input feels the same everywhere, from one table (`src/ui/input_feel.h`):
  - A wheel notch zooms every canvas by 2^0.2, about 15%: the Scene's camera, its view zoom and the UI Canvas (⌘ or Ctrl with the wheel), and the graph, as Blender's views and xyflow do. A trackpad's fraction of a notch zooms by that fraction, and a pinch zooms with the fingers. One event never more than doubles or halves a zoom.
  - A notch scrolls lists, panels, menus, the palette and the Text Editor 100 points, what a browser scrolls, so trackpad content moves with the fingers. That is about four compact rows.
  - Each event counts once, in the frame it arrives, at any frame rate.
  - A press becomes a drag after 4 dp: Scene objects, graph nodes, wires and reroutes, dragged rows and tiles, and scrubbed numbers. Holding still never starts a drag, so a slow click still clicks. A double-click is two presses within 500 ms and 3 dp.
  - Tooltips open once the pointer rests 500 ms, and within 400 ms of one closing the next opens at once (Base UI).
  - Wheel directions arrive as the system reports them, natural scrolling included.

## RmlUi port contract

The CSS uses only what RmlUi 6.3 supports: flexbox, `gap`, absolute positioning, `var()`, border radius, solid fills, transforms, transitions, `box-shadow`, `filter` (blur, drop-shadow, opacity and the color functions), `mask-image`, the `linear-`, `radial-` and `conic-gradient` decorators and their repeating forms, and `overflow` clipping that follows border radius. The backend renders the effects on the GPU, as RmlUi's GL3 renderer does, and RmlUi caches a box-shadow until its element's size, colors or opacity change. It uses no grid, `calc()`, pseudo-elements, `outline` or `!important`. State selectors use the same `data-*` attributes. Porting a rule means:

- `px` becomes `dp`.
- `ms` durations become seconds, and `cubic-bezier(.23,1,.32,1)` becomes `cubic-out`.
- `border: 1px solid c` becomes `border: 1dp c`.
- `:root` becomes `body`.
- Reduced motion becomes `@media (theme: reduced-motion)`.
- `font-variant-numeric` becomes the embedded GeistNumeric face.

Required native work:

1. **Host.** One RmlUi context per window, with no ImGui container windows. RmlUi lays out a whole document whenever anything in it changes, so Studio is several documents in that context, as a page shows `<iframe>`s (`src/ui/iframe.h`): the shell (`studio.rml`) lays out the places of the top bar, the areas, their splitters and the status bar; each area, the top bar and the status bar is a document of its own over its place (`kit_document_begin`), so a change inside one lays out only that one; and the overlay layer, a document above them all, holds popups, menus, tooltips, toasts, the palette, dialogs and the drag overlay, which `src/ui/drag.c` puts in the topmost document. Focus, keys, hover, data models and textures cross between them. The backend needs `SetMouseCursor` for scrubbing and splitters, relative-mouse mode for pointer lock, and the Symbols font loaded as a fallback face.
2. **Controllers.** C controllers implement the kit contracts: Layers/Positioner, Menu/Menubar/ContextMenu, Tooltip, NumberField, Select, ToggleGroup, Checkbox, Collapsible, Command (a `command-score` port), Splitter and Tree. They mutate only view state and emit C actions.
3. **Custom elements.** `<viewport>` shows the scene render target as a callback texture. `<graph-wires>` emits Bezier geometry. The color plane uses the vertex-gradient decorators, which need no shaders. `<number-flow>` and `<morph-text>`, with `presence` on `data-if` elements, carry NumberFlow, Torph and Motion's presence into authored UI, the editor's and games' (`src/ui/motion.h`). The native controls `<number-field>`, `<color-field>`, `<splitter>` and `<live-text>` (`src/ui/controls/controls.h`) are the kit's number fields, color pickers, splitters and live labels too, so native and authored panels share one implementation; their values repaint without laying out the document.
4. **Model boundary.** Selection, values, overrides, history, dirty state and playback stay in the C authoring layer. The view syncs from it and never owns it.

## Migration plan

Studio is the only editor, on desktop and in the web build; the ImGui workspace is gone.

| Phase | Replaces | Result |
| --- | --- | --- |
| 0 · Foundation | ImGui window hosting for RmlUi, and the ImGui input path in `retained_menu.c` | A full-window document, input and focus routing, text input and IME, cursors, icons, overlay layer, the kit RCSS and controllers |

Behavior changed from the ImGui editor:

- A scrub, a typed entry or a picker session is one undo step.
- Undo, Redo, Save and the dirty mark follow the active document. A prototype document has its own history.
- Override marks and a field context menu with Reset to Prototype replace the per-field revert buttons.
- Output, Assets and Performance open in a drawer at the bottom of the main column, from the status bar, the View menu, ⇧⌘A and ⇧⌘U. The drawer eases open in 200 ms and closed in 100 ms, and its height persists.
- Splitters, scrubbed fields and text inputs show resize and text cursors.
- Preferences live on a Settings page (the gear, Mod+, or the `settings` command), as VS Code's settings editor: Editor and Project tabs, a category sidebar (Appearance, Scene, Graph, Text Editor, Keyboard), search across labels, descriptions and keywords, and a row per setting with its description, control, a modified mark and Reset. Keyboard records a shortcut for any command, shows its aliases and area context, marks a chord another command shares where both act, counts those conflicts in a badge that searches for them, and resets overrides to the defaults; Project sets the project name, start scene and default root document in `project.kdl`. Every preference is a row of one table (`studio_settings[]`, `studio_settings.c`) that the preferences file, the saved keys panels bind and the page share; they persist, with the area layout, in `studio_prefs`.
- One selection, as Unity's, Godot's and Blender's: the Scene outlines every selected object in orange and the active one brighter, the Outliner highlights their rows with the active one's a step stronger, and the status bar counts them ("Objects 3/21"). In the Outliner <kbd>⌘</kbd>-click adds a row to the selection or takes it out, <kbd>⇧</kbd>-click selects the rows from the anchor (the last row clicked) and <kbd>⇧↑</kbd> <kbd>⇧↓</kbd> extend it, while a right click keeps a selection it lands in. In the Scene <kbd>⇧</kbd>- or <kbd>⌘</kbd>-click adds an object or takes it out, except on a gizmo handle, where Shift keeps the aspect ratio, and a marquee with either held adds what it touches. The clicked object becomes active; taking the active one out makes another selected one active. An Undo of a step that changed several objects leaves them selected.
- Duplicate, Delete, Frame, Hide, Copy and Cut act on every selected object, each one Undo step; Rename acts on the active one. Duplicates land one grid increment down and right, as Godot's do, so they show beside their originals and stay on the grid with them (Unity's copies in place hide behind what they copy), and become the selection. Delete and Cut show a toast with Undo for six seconds, while they are still the latest edit. Save reports success in a toast; a failure stays until it is closed.
- Copy puts the selected objects on the system clipboard, the browser's in the web build, as scene text: a scene document's entities, each its prototype, overridden fields and behaviors (`scene_copy_selection`). Paste (Edit menu, the Outliner row menu, <kbd>⌘V</kbd>) adds them to any scene of a project that has their prototypes, in another session too, as one Undo step: keeping their names unless taken (then `Prototype_N`) and their layout, centered under the pointer while it is over the Scene, else one grid increment from where they were copied, moved by whole increments while snapping, and selected. Text that holds no objects, or names a prototype the project lacks, pastes nothing and says why in a toast. A focused field keeps <kbd>⌘C</kbd>, <kbd>⌘X</kbd> and <kbd>⌘V</kbd> for its text. Paste waits while collaborating.
- With several objects selected, Properties is Unity's multi-object editor: its header counts them and has a chip per prototype among them, which narrows the selection to that prototype's objects; the tabs show the components every selected object has; a field whose values differ shows a dash (`KIT_MIXED`, `data-mixed`: an empty number or text, a dashed checkbox, an unchosen select, a faded swatch); and a change writes every selected object as one Undo step, a vector only the axes it moved, while Reset to Prototype resets each to its own prototype's value. Behaviors stay single-object.
- Status-bar reports fade after three seconds. The full operation history is in Output ▸ Info.
- The transport target is a menu: the scene, or a preview of the open or selected prototype. Its label morphs when the target changes.
- Playback speed sits after the transport, as Unity's Time.timeScale and Unreal's slomo: a compact button reading 1× opens 0.1×, 0.25×, 0.5×, 1× and 2×, with Slower (<kbd>⌥⌘-</kbd>), Faster (<kbd>⌥⌘=</kbd>) and Normal Speed (<kbd>⌥⌘0</kbd>), also in the Play menu. It scales game time, so behaviors, physics, particles and material time slow alike, while frames draw and the editor responds at the display's rate; Step still advances one fixed tick. Away from 1× the button is marked and the status bar shows the speed, a click there restoring 1×. Stop returns to 1× and nothing persists, as Play Mode resets Unity's timeScale, so a fresh Play never starts slow.
- The Outliner root collapses with its twisty, a double click or Left and Right, and Up and Down step the active row while the pointer is over it, Shift extending the selection. Its list is one Tab stop, as Unity's Hierarchy is focusable: while the keyboard holds it the active row shows the focus ring and the Outliner's keys act wherever the pointer is, until a click moves the focus. It is authored (`Outliner.rml`, `OutlinerHeader.rml`) over the `outliner` panel source.
- Objects hide from the Scene or lock against picking there, as Blender's Outliner eye and selectability toggles and Unity's Scene visibility and pickability do. An Outliner row's eye and lock show while it is hovered or while they are on, and take the row's full height, so a press above or below their icon toggles rather than selects; a hidden object's row dims; Alt+click on an eye shows that object alone, or all of them again. Over the Scene or the Outliner, H hides the selection, Shift+H the rest and Alt+H shows all (View menu, Blender's keys), and the status bar counts the hidden objects, a click there showing them. While the scene is edited its view draws no hidden object, its UI included, and picks and marquees neither hidden nor locked ones; the Outliner still selects them, and Play shows everything. It is the editor's state, never the scene's or its Undo's: kept per scene file and object name in a user file beside the preferences (`scene-view.json`, `chibi.sceneView` on the web), it follows renames and Save As, and a deleted object's goes.
- Prototypes dragged from Assets land where they are dropped in the Scene; behaviors dropped on an Outliner row or a Scene object attach to that object.
- One drag serves every document (`src/ui/drag.c`), as Unity's `DragAndDrop` serves its windows and Unreal's `FDragDropOperation` its panels: authored lists and native ones drag into each other across areas, and C surfaces such as the Scene take drops. A tree row splits as Unreal's `EItemDropZone`: its top and bottom quarters drop above and below it, its middle onto it; a row that holds nothing splits in halves. The widget gallery's List, TreeRow drop zones and Tile samples show it with the project's assets.
- An asset an object's field names (a material, shape, ui document, field or system) drags from Assets onto that field, as Unity's object fields take one and Godot's inspector marks the pickers that accept it (`studio_drop.c`). While it drags, every Properties field of its kind and every Outliner row whose object has such a field takes a soft primary border (`data-drop-accept`). Over one, the field shows the asset's name in primary and the Scene shows the object with the asset, outlined in the drop color, for that draw only, as Unity previews a material dragged over an object; over the Scene, the object under the pointer takes it the same way, and the overlay's second line says what a drop does ("Assign to Enemy_2", or which kind of object takes it). Release assigns it as one Undo step, to every selected object from a multi-object field; Escape, or a release anywhere else, leaves everything as it was, since the preview never leaves the draw. The status bar shows Release to drop and Escape while a drag runs.
- An instance's prototype actions sit in the menu beside its prototype in Properties (⋯), the Outliner's row menu, Object and Search. Apply Overrides to Prototype… lists the fields the instance overrides, outside its position, each checked with its value, as Unity's Overrides dropdown does, and says how many other instances inherit them and will follow; Apply copies the checked ones into the prototype, those instances take the values, ones that override a field keep theirs, and one Undo step puts the prototype and them back (also a step of the prototype's own document). A field's menu offers Apply to Prototype beside Reset to Prototype. Save as New Prototype… names an asset, offering the object's name, refuses one an asset or file has, saves the tuned instance as that prototype, its components, values and behaviors with its old prototype's position, and makes the object an instance of it, as Unity's new prefab from an object and Godot's Save Branch as Scene do; Undo makes it an instance of its old prototype again and keeps the asset, as both editors keep theirs. Each reports in a toast with Undo, and waits while collaborating.
- Assets draws each asset as it looks (`studio_thumbnails.c`): a scene a few frames into its start, framed as the Scene view frames a scene it opens (its objects fitted, widened to what its GameCamera sees, as Godot's scene previews fit their content), its streamed terrain filled in first, and lit where a pixel holds no more world than the Scene view's (3 units, up to 1024 pixels) before it shrinks, so its light looks as the Scene view shows it; a prototype fitted on the project's stage, its HRC lighting and material worlds, as Unity's prefab thumbnails; a material as a disc of it, a sphere in perspective scenes; a shape filled; a field's values as previewField bakes them; a ui document on the Canvas's backdrop, with a widget laid out on a screen its size; a stylesheet's colors; a graph asset as a mini-map of its nodes and wires, as Blender's node groups and Unreal's material functions show theirs. An asset with nothing to draw, such as a camera's prototype or an empty graph, keeps its kind's icon, and a tile shows that icon until its thumbnail is ready. Thumbnails render only for the tiles in view, cheapest kinds first, within a 4 ms frame budget (a scene streams terrain, runs a frame and draws a light pass a step), and follow the live asset, as Unreal's do: an open document's unsaved edits, and their Undo and Redo, show once edits rest for 0.6 s with no mouse button held, so a drag or a scrub never renders mid-gesture; saved assets render again within a second of a change to the content of their file or a file they use. A scene whose terrain still streams after 2 s shows what has streamed, with a spinner in the tile's corner, until the rest has. Pictures of saved content persist between sessions, as Unity's Library and Unreal's Derived Data Cache keep theirs: PNGs keyed by the content they show, beside Studio's preferences (`thumbnails/`, or `$CHIBI_THUMBNAIL_CACHE`; empty turns it off) and in IndexedDB on the web, trimmed least recently used first past 64 MB (16 MB on the web), so a cold start shows unchanged assets at once. Rendering never changes authored data, the open scene or its runtime. The kind badge sits in a thumbnail's corner, as in Unreal's tiles; the name ellipsizes and its tooltip holds the full name, kind and uses, with a 256 dp preview once the pointer rests 500 ms, as Unreal's hover thumbnail. A click selects; the arrows, Home and End move the selection and Enter opens it. The palette's asset results show the thumbnails Assets has made. The size slider, Unity's, persists in the preferences; a list is a step on it rather than a separate view toggle.
- Shortcuts follow the platform, including the web build on a Mac: Command is the primary modifier, chords are written ⇧⌘Z, and Command edits text in fields. The browser does not act on Command chords while Studio has the page, and Option chords such as ⌥G arrive as their letter.
- Scrolling in the graph zooms, from a mouse or a trackpad.
- The graph editor owns Undo, Redo and Save while the pointer is over it, or, from a menu, while it was clicked last. Space and Shift D there do not play the scene or duplicate objects.
- A node spawned from a dragged wire lands with the wired socket at the drop point. The search lists exact type matches first, then conversions, then wildcards.
- Nodes that no event reaches, or whose values nothing reads, are dimmed. Wires attached to the selection or the hovered node stand out, and the rest recede.
- While the game runs, the open behavior shows one running instance, its debug target, as Unreal's debug object does. Selecting an object in the Scene or the Outliner, a spawned one included, or opening a behavior from its buttons, targets that object's instance; selecting something without the behavior keeps the target, and a behavior with one instance targets it. The graph header's target menu lists every instance running the behavior, searchable, under Scene and Spawned, after No target, which shows no live data until the selection changes. Only the target records what runs, and only while a graph shows it; other instances and the compiled code they run pay nothing.
- Short-lived spawns stay in reach. Under Follow newest, the target menu lists each prototype that attaches the behavior, as Unreal's debug filter picks by class: the target moves to each instance of it the game spawns, from its first frame, and the button reads "Newest <Prototype>" until one runs, then "<instance> · Newest", until an instance is chosen or selected. When the target's object is destroyed, the graph keeps its last values, pulses (which ease out) and node runs, frozen, and the button reads "· Destroyed", until another target is chosen or Follow newest picks the next spawn; the behavior world keeps that one instance, which no longer runs, while it is the target. Under Break when spawned, the same menu, a prototype's Assets menu and an object's Outliner menu toggle Break When Spawned (for the editor session): Play pauses after the frame that spawns one, selects it and so targets its instance, and reports which spawned. A breakpoint that stops a run also selects that run's object, as Unreal's debugger does. Conditional breakpoints are not built.
- Wires the target ran pulse: bubbles in the wire's color travel from source to target at a constant speed on screen, whole while the wire keeps firing (a fire within the last 0.1 s), and shrink to nothing over 0.4 s once it stops, on the editor's clock, so a paused game stills them too. A data wire carries a value when its consumer reads it, as pure values are pulled, so it pulses as often as that consumer runs. Execution wires also glow for two seconds after they run. A node the target is running wears a rim that fades the same way, and its title's tooltip tells how often it ran and when last. Reduce Motion trades the bubbles for the glow; below 15% zoom they go.
- Hovering a pin while the target runs shows the value it last carried, and Show Live Values (the graph's View popover, View ▸ Live Values, Settings ▸ Graph) puts a quieter chip with that value beside every data output: numbers to about three digits, vectors as (x, y), colors as a swatch and hex, entities by name. Values come from the target's latest completed run of each event and refresh ten times a second, so they hold still to be read; a pure value reads as what its consumer received.
- Scrubbing a node's inline value is one undo step.
- Saving a scene keeps its file name as the document name. It used to write "Scene".
- A field that names an asset, such as `GameUi.document` or the Scene tab's root document, is a select that searches the project's assets of its kind on the command surface, with None and, where a name may be missing, the typed name. A name no asset has shows as invalid.
- A game UI's error shows in the Scene's notice line and heads Output's Problems; Output records each new error once.
- While a ui asset's document is active, the Scene area is its Canvas: the asset alone in the Scene area over an empty world, as Storybook shows a story: at a screen size (Fit, Phone, Tablet, Desktop), on a light or dark backdrop, magnified by the view zoom, with an Actions log of the events it emits and what uses it. Its events reach no behavior. Preview UI Asset… in the command palette, Preview in an asset's Assets menu and the Canvas's crumb show any ui asset the same way.
- The other areas follow a ui asset's document too, as Unity's UI Builder and Unreal's UMG Designer arrange theirs (`studio_designer*.c`):
  - The Outliner is its Hierarchy: each element as `tag#id.class`, a `<use>` by its widget, with its only text. Rows select, fold (Left and Right), filter and walk (Up and Down). Dragged, a row drops before or after another in its top and bottom quarters and inside it in its middle. Its menu adds, duplicates (⇧D), wraps in a div, opens the source or a widget, and deletes (X), with Undo in a toast.
  - Properties is its Details: the element's text, widget, id, classes as chips, attributes and bindings (in code), its inline style, and the rules of the document's RCSS that match it, each value in the control its property calls for (lengths scrub with their unit, colors pick, keywords choose, the rest is text). With nothing selected it lists every rule.
  - Assets is its Library: elements and the project's widgets as tiles, dragged into the Hierarchy or the Canvas, or clicked to add to the selection.
  - The Canvas outlines the element under the pointer and the selection, labeled with its size, and a click selects there. The selection has resize handles on its right and bottom edges and corner, as Unity UI Builder gives an element in the flow: dragging one resizes only the element, wherever its layout puts it, following the pointer at the Canvas's zoom and the document's scale, the label reading the size. Shift keeps the aspect at the corner. Only the Canvas shows the size until release writes `width` and `height` in whole dp into the element's inline style, as content or border box as its `box-sizing` says, one undo step; a press that never leaves the handle writes nothing, and Escape puts the element back.

  Selecting in any of them, or moving the Text Editor's cursor, selects in all, and the Text Editor's cursor moves to the selection. Every change is one text edit of the document and one undo step; a scrub or a color session is one step.
- The Add menu offers the events that the GameUi documents on whatever attaches the open behavior send, described by what the player does ("Sent when the player clicks #extract in Bank").
- Objects rename in place, as in Blender and Unity: F2 over the Outliner or the Scene, a double-click on an Outliner row, Rename in the row's menu or the Object menu, or the name at the top of Properties' Object tab, which is a field. Enter or leaving the field renames as one Undo step and Escape keeps the name; a name another object has is refused with a toast. Nothing references an object by its name, so nothing else changes. F still frames a row.
- A prototype's Properties ends with Add Component, which searches the components it lacks on the command surface, grouped by the tab each shows in (Unity's Add Component); the added component's panel opens. A component panel's menu, the header's ⋯ while hovered or a right press on the header (Unity's component menu, Blender's modifier menu), removes it with Undo in a toast. - Play in the Studio project runs Studio itself, since the editor is that project's game: a guest Studio fills the Scene area, built from the project's working copy (unsaved text included) and editing the same scene authoring. It keeps its own preferences while it runs, takes the pointer over it and the keys while it has them (a press in it, or the pointer over it while no host field has the keyboard), and has no Play or Open Project of its own. - The Text Editor finds (<kbd>⌘F</kbd>, VS Code's find widget: Enter and Down for the next match, Shift+Enter and Up for the previous, Esc back to the text), types over a selection, and goes to the start and end of the text with <kbd>⌘↑</kbd> and <kbd>⌘↓</kbd> (<kbd>Ctrl+Home</kbd> and <kbd>Ctrl+End</kbd> elsewhere). Horizontal Split holds the Text Editor beside the Canvas when selected.

## Decisions

1. Density is an editor setting. Compact is the default. UI Scale (50–200%) sizes the whole editor, as Blender's Resolution Scale and Unreal's Application Scale do; games' UI keeps its own scale, in the Scene view and in Play. It steps as browsers and VS Code zoom (<kbd>⌘=</kbd>, <kbd>⌘-</kbd>, <kbd>⌘0</kbd>, View › UI Scale) and its percentage stays in the status bar, as Office keeps its zoom there. The Scene's view zoom is separate from its camera: the wheel moves the camera through the world, while <kbd>⌘</kbd> or <kbd>Ctrl</kbd> with the wheel, or the header's percentage, magnifies the rendered frame with its game UI, as Unity's Game view Scale does; the middle button pans it while magnified. The frame renders sharper up to 200% and magnifies its pixels beyond. An idle editor draws at most four frames a second, as Blender redraws only on events: input, a running scene, a frame that draws anything the frame before it did not (so animations need no registration), or RmlUi's next update (a caret blink) bring back full rate, and a write that leaves a style unchanged lays nothing out.
2. Areas (Blender splits) replace floating docking.
3. Properties tabs, prototype icons, and number ranges and units are authored per project in `content/editor/Components.kdl` (`src/editor/documents/component_presentation.h`). Studio re-reads the file within a second of a change. An invalid edit keeps the last valid file and reports the error; without the file, components show under Object with no icon and plain numbers.
4. Orange selection in the viewport, the active object brighter than the rest, as Blender's; blue in lists. The graph's selection color is still open.
5. Studio's own UI is moving to authored assets, built the way games build theirs. `projects/studio` holds the editor's ui assets, widgets and a `Studio` scene whose GameUi entities are panels. Studio runs that scene as a small world and mounts a panel's document in a kit host (`kit_host`, `src/editor/studio/studio_ui.c`), where Studio's stylesheets and theme variables apply. Its RCSS is scoped to the panel. Preferences are that world's saved keys, so a binding such as `data-checked="save.theme"` edits them. The Behavior header's view popover, the Settings page, the status bar, the top bar and the area headers are authored this way. The status bar (`StatusBar`, with a `KeyHint` per hint) binds Studio's `editor` variable, and its drawer toggles run commands with `emit('studio.toggleAssets')` and read them from Studio's `commands` variable (each command's label, shortcut, icon, enabled and checked); UI Scale and its menu stay native in the bar's `#ui-scale` element, a native slot (`kit_slot_begin`), as Unity's IMGUIContainer hosts IMGUI in UI Toolkit, and its authored controls retain keyboard focus. The top bar (`TopBar`) lists `editor.tabs`, whose faces and close buttons run `emit('studio.selectTab', i)` and `emit('studio.closeTab', i)` with the tab's index, and binds the transport, the gear and Search to `commands`; its `#menus` lists the menubar's menus as markup (`<menu label>` holding `<li command="id">`, `<li list>`, `<li label>` headings, `<hr/>` and submenus), which the native menubar draws in `#menubar`, and the play target's menu and a paused run's debugger steps stay native in its slots. Each area shows its own `AreaHeader`, which binds its item of `editor.areas` as `area` (`data-alias-area`, as a widget's props): Maximize, faint until hovered and Restore while its area fills the workspace, runs `emit('studio.maximize', area.index)`, and the drawer's Close `closeDrawer`; its editor type menu is an authored `Menu` over Studio's `choices` variable (`choices.editors` and `choices.panels`), which sends `emit('editor.type', area.index, type)`, and the editor's own controls stay native in its `#controls` slot, where a field keeps the keyboard. Menus and popovers are the HTML popover attribute (`src/ui/popover.c`): `<button popovertarget="id">` opens `<div popover id="id">`, and one stack holds them with the kit's popups and the color picker, so an outside press and Escape close the top first; a menu's highlight, typeahead, submenu delay and menubar switching are popover.c's, with the widgets Menu, MenuItem, MenuCommand (a command's label, icon or check, shortcut and state), MenuGroup, MenuSeparator, Submenu, MenuCheck, MenuOption, ChoiceList, EnumField and AssetField. An open popover's document stacks above the other areas, so a menu reaches over the next area whichever has focus. The Behavior header's View menu (`GraphView`) is its button and a `Menu`. Events follow the web and Vue (docs/studio-rml-migration.md, Events): `emit('name', ...)` passes up to four arguments, and its activation carries the event's modifier keys, button and pointer and its sending element, where a popover anchors; `studio.<id>` runs a command and `<source>.<action>` the action of a panel source in `studio_sources.c`'s table (Settings' Record sends `settings.record` with its row's key), and other events reach the panel's behaviors; a right press sends `contextmenu`; text fields send `input` on each edit and `change` once an edit commits (Enter, or leaving the field), which `data-value` and `data-value-lazy` follow; and `data-when` builds or removes its element, as Vue's `v-if`, where `data-if` only hides it. Studio syncs a panel source only while its panel shows, and dirties only that source's variable. The Settings page binds Studio's `settings` variable (`studio_sources.c`) through reusable widgets games can use too (Switch, Select, Slider, Segmented, SidebarNav and SettingRow); its controls take focus natively, with RmlUi's `nav` properties moving between them, a `NavKeys` behavior makes the sidebar's selection follow Up and Down, and a `Dismiss` behavior hides the page's GameUi on Escape, the close button or a backdrop click. Panels start with their GameUi hidden, so opening the Studio project never draws them over its scene view; selecting one there shows it while the scene is edited (Play runs a guest Studio, as above), a prototype preview shows it, and Studio's popover hosts show them regardless, and a modal panel shows while its entity's GameUi is not hidden, in a `kit_modal_host` above the editor, and global shortcuts remain available from non-text chrome buttons and document tabs while open popups and modals keep their keyboard ownership; text fields keep their keys but pass Studio's other ⌘ chords. Editing a panel's assets or behaviors applies within a second, and an invalid edit keeps the last valid version.
6. Every panel of the Studio scene is also an editor type, listed after the built-in editors in an area's editor menu, the way Blender lists Preferences. An area shows its panel whether or not its GameUi is hidden. Data lists the saved keys of the world the Scene shows, and Theme lists the custom properties of the stylesheets the open scene's root document imports, a section per file and rule; both edit in place (Enter or blur commits), so with the Studio project open they change the editor's preferences and look.
7. The UI Inspector inspects every UI surface Studio draws, as Chrome DevTools, Unity's UI Toolkit Debugger and Unreal's Widget Reflector do: its chrome, its authored panels, the graph canvas, and a game's UI in the Scene at any view zoom. <kbd>⇧⌘C</kbd>, Inspect Element in the palette, or the panel's Pick starts picking. The element under the pointer is highlighted in DevTools' box-model colors, a click selects it, and <kbd>Esc</kbd> ends picking. The Inspector is itself a panel of the Studio scene, so it can inspect itself. It opens in the drawer when no area shows it, and shows:
   - the Elements tree, with the widget each element shows;
   - Styles by rule, with each rule's file and line;
   - Computed values and Attributes;
   - Force state;
   - Edit Source, which opens the ui asset at its line in the Text Editor.

   Kit chrome reads Native (C), with its kit path.

Field dropdowns and autocomplete show at most seven option rows by default and scroll through the remaining choices. Their cap follows density and font metrics; a smaller viewport may reduce it. Action menus use slimmer rows, display all actions when space permits, and scroll only when their content exceeds the viewport. Command palettes retain their larger browsing layout.

Autocomplete uses compact code-sized rows, a subtle border and neutral selection that preserves name, match and type colors. Wheel and keyboard scrolling remain available. Code completion shows a scrollbar only when its choices overflow; graph field completion keeps its compact list without scrollbar chrome. Editable source fields show dotted property paths; folded expressions show their source and can be edited in place. Expanded expression source also enters editing when clicked, within the node's existing width. Expressions remain an optional calculation tool alongside typed constants and bindings.

Form controls keep familiar keyboard, commit and cancel behavior ([Jakob's Law](https://lawsofux.com/jakobs-law/)). Named choices support search and useful groups ([Hick's Law](https://lawsofux.com/hicks-law/)); labels stay close to their inputs ([Law of Proximity](https://lawsofux.com/law-of-proximity/)). The full control and its label act as targets, and related actions stay near their field ([Fitts's Law](https://lawsofux.com/fittss-law/)). Search and keyboard changes show immediate feedback, while pending work reports its actual state ([Doherty Threshold](https://lawsofux.com/doherty-threshold/)).
