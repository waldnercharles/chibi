1. **Runtime source policy changed without an ABI bump.** Published runtime `.2` is pinned to source `5c28191b3ea53afa232c34e37b14fd9b01024aef`, tree `94ebca0fd1fb18e9463aec1cdf8d993ebd368918`. Reusing the old binary's size/hash under a new label cannot establish this native policy compatibility.
2. **The pure input selector is already correct.** Shared script `Prepare` validates original package membership, copies bootstrap.json/compiler.chibip/runtime.json plus manifest-listed .chibi sources, and retains its native-source refusal. Current manifest has 19 sources across 11 complete selected package folders: 18 compiler files and core strings/Strings.chibi. Static reads confirmed their current byte counts/hashes and explicit imports. The two generated asset_compiler_packaged.c wrappers are excluded. Expected isolated initial inventory is 23 files, including one runtime executable; this replaces the former main proof's 44-file inventory. Future artifact readers must understand the new 19-source/request/contract evidence schema instead of reusing that old count. Do not rewrite the selector or substitute asset_compiler/CompilerSources.txt, which omits the new Bootstrap.chibi member. Keep exact manifest/package completeness, source-byte counts/hashes and no-native-source checks.
3. **The shared script currently cannot drive either runtime's artifact CLI.** Its stage and contract calls at lines235/243 omit --timeout-ms. `src/toolchain/compiler_main.c:295` requires a positive value; --target-json bypasses that gate. The old pinned source has the same artifact invocation requirement. Fix the caller, preserving the CLI contract.
4. **Generic execution and native source recovery prove different paths.** Current Prepare/Prove uses --artifact/--output-artifact and calls each output's compiled BootstrapContract. This proves pure compilation and byte identity, but bypasses native validated()/recover(). A new native host must also prove --bootstrap/--recover on the isolated KDL-free source closure. That CLI route rejects artifact-only timeout flags.
5. **Exact source matters to local recovery checks.** The existing `bootstrap_recovers_from_a_clean_checkout` fixture exports HEAD through git archive. Before the pending typed commit, it validates HEAD30cd sources rather than the staged0b5 combination. Preserve this distinction; require a clean committed-candidate recovery check after the validated checkpoint.

## Compatibility boundary clarification

The preserved `.2` runtime has a generic `--artifact` route independent of its old native `--bootstrap` source policy. The normal consumer invokes that generic route, not `--bootstrap` or `--target-json`. Removing bootstrap.kdl therefore does not by itself make the generic consumer incompatible. Its eligibility depends on the actual prepared ABI/native catalog, valid invocation arguments, compiled output contracts, and both executed stages reproducing identical bytes. This source-only preparation does not claim that the current typed candidate has passed that execution proof.

The isolated patch deliberately keeps `.2` and both new-host-only consumer flags off while fixing the required generic timeout arguments. A matching new native host remains required before adopting KDL-free native recovery or independent target queries. The current patch enables NativeRecovery/QueryTarget only in the separate native producer; later published-host interface adoption is a separate pin-and-consumer decision. A native producer pass does not substitute for the ordinary consumer proof.
