# Tutti Space Program fluid reference

Checked 2026-10-02 against [the live app](https://tsp.grantkot.com/) and its publicly served JavaScript. This is compiled deployment evidence, not a recovered native solver implementation or benchmark. Grant Kot describes Tutti as WebAssembly with multithreading and SIMD plus WebGL on [his own site](https://www.grantkot.com/).

## What the deployment establishes

- **MPM interface, CPU simulation, GPU rendering.** The runtime initializes `_mpm_init`, submits `_mpm_update_mt`, reads `_mpm_get_render_data`, and configures substances, reactions, heat, grids and gravity through `_mpm_*` exports. Emscripten uses shared WebAssembly memory and pthread workers; its worker pool is allocated from `navigator.hardwareConcurrency`. Rendering explicitly creates WebGL2 and uploads snapshots from the Wasm heap. No WebGPU simulation backend appears in this path. This identifies the engine as MPM at the interface level; it does **not** establish MLS-MPM, APIC, constitutive equations, pressure solver, CFL rule, or internal substeps. [Served runtime](https://tsp.grantkot.com/assets/singleton-CC0WmPkn.js)
- **Large initial population, not a proven capacity.** The default `initialScene` is `nbody` and initialization calls `initNbodyTestScene(..., 3e5)`, ultimately passing 300,000 to `_mpm_init_nbody_test`. The renderer domain is 9,216 × 9,216 world units, and initialization passes `(144,144)` to `_mpm_set_grid_size`. The latter's units/meaning are unavailable; do not call this a 144² fluid-cell grid. Neither this count nor the `wl=200000` drawing-point cap establishes the solver's maximum population. Actual particle count changes with user edits and merge/split. [Runtime](https://tsp.grantkot.com/assets/singleton-CC0WmPkn.js), [material manager](https://tsp.grantkot.com/assets/mpm-material-manager-BQQNFGyQ.js)
- **Fine particles with deforming geometry.** Water and oil have authored cold/hot size 1.0; liquid surface-tension values are 0.78 and 0.48 respectively. The visible particle vertex shader mixes previous/current centers, scales size by `sqrt(mass/unitMass)`, clamps render size to 1–8 world units, and transforms quad corners with the supplied deformation gradient. `drawArraysInstanced(TRIANGLE_STRIP,0,4,particleCount)` draws these particles. They are not fixed circular blobs or necessarily one physical unit per pixel. The `gl_PointSize=2.0` shader is a lighting splat, not the main particle geometry. [Catalog](https://tsp.grantkot.com/assets/mpm-material-manager-BQQNFGyQ.js), [shaders and draw calls](https://tsp.grantkot.com/assets/singleton-CC0WmPkn.js)
- **Adaptive work and smooth presentation.** Statistics expose active fine/local/global tiles; interfaces include fine-grid/coarse-interpolation, occupancy merge/split and cheap-gas controls. Default settings enable merge/split and cheap gas. Physics dispatch permits one outstanding asynchronous job, schedules against a 60 Hz interval, and interpolates completed snapshots for drawing. The 60 Hz scheduler is not evidence for a single internal solver substep. Default gravity includes N-body plus radial attraction, which affects the showcased motion. [Runtime](https://tsp.grantkot.com/assets/singleton-CC0WmPkn.js), [default settings](https://tsp.grantkot.com/assets/index-DOpwS2Bp.js)

## Implications for Chibi / Neon Swarm

The first return comes from reducing **simulation spacing and visible footprint together**, keeping material density/mass and thermal capacity consistent with area. In 2D, halving spacing for the same filled area requires about four times as many particles; reducing sprite size alone leaves holes and does not improve motion resolution. Establish a screen-space target at the gameplay camera, then measure equal-content scenes with smaller spacing, kernel support and visible size.

Use snapshot interpolation and small instanced fluid geometry to remove coarse stepping. Flow-aligned deformation is a separate rendering experiment; a velocity-stretched sprite is only an approximation of Tutti's supplied deformation gradient. Keep HRC emission/absorption consistent with the finer coverage.

Tutti provides concrete reason to benchmark a sparse tiled **CPU MPM backend** for dense interacting fluids, grains and deformable solids, especially with native threads/SIMD and WebAssembly threads/SIMD. Compare at equal visible detail and material volume against the present solver, including collision, heat, rendering/upload and lighting costs. Merge/split, active tiles and specialized gas work are relevant architectural ideas, but their algorithms cannot be inferred from export names. Do not promise 300,000 particles at our frame budget or replace destruction/rigid bodies from this evidence alone.

No native source repository, solver equations, current-device timings or hard population limit was found in the primary sources inspected. Deployment filenames above are content-hashed and may change.
