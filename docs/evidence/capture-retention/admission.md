# Managed-capture retention baseline admission

Base: `02f8453211dd4cc57965ba52c645f08a92e53c5e`.
Worktree: `capture-retention`. No production behavior changes.

Proposed first measurement: existing `language-program` and `wasm-program`
selectors through the production supervisor in `tools/test_policy.py`.
Configuration/build time is separate. Native ASan/UBSan, leak detection disabled
because this host is traced; actual Node-hosted Wasm, not a bytecode substitute.
All original program assertions remain unchanged.

Three new C pico_unit cases, fourteen finite scenarios total:

- Detached scalar string and detached two-string array element overwrite, each
  with normal completion, writer then final-holder cancellation, and owner
  detachment. Each combination runs bytecode and the real compiled backend.
- Attached scalar-string control with normal completion, on both backends.

Each scenario has one owner, two tasks and one shared local box. The writer has
two aliasing ref parameters; the keeper has one. Strings are exactly 512 bytes
plus NUL, generated by the C fixture with distinct two-character tags. At most
34 strings are produced per scenario. Each source fits a 2,048-byte buffer.
There are 32 writes and at most 41 synthetic updates; cancellation/owner detach
occurs after 16 writes. All 14 scenarios together have at most 382 updates, including one cleanup update per cancellation scenario.
Each dispatch/update has an instruction budget of 10,000. No sleeps, rendering,
network, disk fixtures, browser or extra processes beyond the existing Node
Wasm runner. No new dependency or standalone executable.

At start and after 8, 16 and 32 writes, report box used/capacity/backing bytes,
its holder count, activation payload usage and the size of a fresh owning
snapshot of its current value. Box backing must remain below 256 KiB in these
finite fixtures. The current snapshot stays below 2 KiB; each temporary
measurement snapshot is freed immediately. The audit does not assert that
historical retention is the desired behavior or call retained bytes a leak.

Verify every byte of current and escaped strings, original and eighth-write
snapshots, both aliasing writer references, unchanged second array element,
continued access from the remaining keeper after writer completion/cancellation,
and snapshot correctness after the last holder exits. Verify no remaining box
holders or activation payloads after task completion/cancellation and no
instances/activation storage after owner detach. These are reachable-storage
observations plus ASan/UBSan and the existing last-holder free path, not an LSan
proof or whole-process RSS measurement.

Static audit: `box_detach` snapshots to an ordinary `box->storage` and points the
detached context at that arena. `write_reference_value` snapshots both the new
value and prior root into the same arena, even for whole-value replacement.
Only the last `box_release` frees this arena. `program_collect_payloads` collects
activation payloads, not box storage. Public payload usage omits box storage;
therefore private read-only inspection is intentional in these tests.

Review the workload and baseline patch before running the new cases. No reclamation fix is proposed for execution yet.

`30e46aa46c437706ea78c1c63fa50bb5a46ce3c4945f71c62bbc45ab701fcd8d`

`cancel` marks the activation finished; the subsequent program update frees it.
The corrected case observes both phases and adds one bounded cleanup update per
cancellation scenario, without additional writes or exceeding 41 updates in any scenario. This
correction requires review before another run.
