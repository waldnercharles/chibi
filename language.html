The Chibi language

Chibi uses .chibi files for functions and gameplay logic. Scenes and project configuration use KDL. The .chibi source contains the whole executable asset. Editors keep graph layout, watches and breakpoints in session.

This overview introduces the language through small examples. Game examples assume that the project declares the components, prototypes and input actions they use. See Examples for complete recipes.

Declarations

Use := for a mutable value, : for an explicit type, and :: for a constant.

Example :: library {
    Run :: () {
        score: int = 0
        speed := 120.0
        GameTitle :: "My Game"
        MaxLives: int : 3

        score += 10
    }
}

A numeric literal takes its type from context. Otherwise, its spelling supplies the type. Integer spelling gives int, then int64 or uint64 when needed. A decimal point or exponent gives a double-precision number.

Example :: library {
    Run :: () {
        lives := 3       // int
        elapsed := 0.0  // number
        half := 1 / 2   // 0: integer division
        ratio := 1 / 2.0 // 0.5
        visible := true
        message := "Ready"
    }
}

Constants cannot change. Their initializers must be available at compilation. Mutable values declared inside a function or handler belong to that invocation.

Use elapsed := 0.0 for a timer. elapsed := 0 creates an integer, so adding a floating time step fails. Initialize the timer with 0.0. Beside a typed operand, a literal takes that operand's type. count * 0.5 fails when count is an integer. Use number(count) * 0.5 for a floating result.

// starts a comment. A newline can end a statement. Semicolons separate multiple statements on one line.

Example :: library {
    Run :: () {
        score: int = 0
        // Increase the score once.
        score += 10
    }
}

Values and operators

Common value types include bool, int, number, string, entity and arrays. number uses double precision. float, double, byte, and fixed-width signed and unsigned integer types are also available.

Example :: library {
    Run :: () {
        health: int = 100
        damage: int = 25
        paused := false
        remaining := health - damage
        alive := remaining > 0
        canFire := alive && !paused
    }
}

Arithmetic uses +, -, *, / and %. Comparisons use ==, !=, <, <=, > and >=. Boolean expressions use &&, || and !.

An explicit conversion calls the destination type. Floating-to-integer conversion requires a call such as int(value). Integer narrowing checks that the value fits. wrap keeps the low bits. clamp limits the value to the integer type's bounds.

Example :: library {
    Run :: () {
        value: int = 300
        checked := byte(value)      // Fails: 300 does not fit in a byte.
        wrapped := byte(wrap: value) // 44
        limited := byte(clamp: value) // 255
    }
}

Integer arithmetic wraps on overflow. Floating-to-integer conversions truncate toward zero, clamp at the bounds, and map NaN to zero.

A character literal contains one Unicode scalar. A string contains text. Runtime strings cannot contain embedded NUL bytes.

Example :: library {
    Run :: () {
        separator: char = '/'
        letter := '🐈'
        label := "Player\nReady"
    }
}

Functions

A function names its parameters and result type. Calls pass arguments in parameter order.

Example :: library {
    DamageFor :: (level: int) -> int {
        return level * 2
    }

    DamageAfterArmor :: (damage: int, armor: int) -> int {
        if damage <= armor { return 0 }
        return damage - armor
    }
}

Arguments can also name a parameter. Parameters can declare defaults.

Example :: library {
    Bonus :: (points: int, multiplier: int = 2) -> int {
        return points * multiplier
    }

    Reward :: () -> int {
        return Bonus(10, multiplier: 3)
    }
}

A function without a result annotation infers its result from the first return. Recursive functions must declare their result types.

Example :: library {
    Double :: (points: int) { return points * 2 }
}

A function with results must return on every path. Multiple results use names and return in signature order.

Example :: library {
    SplitDamage :: (damage: int) -> (shield: int, health: int) {
        return(damage / 2, damage - damage / 2)
    }
}

Parameters normally receive value copies. A ref parameter writes to the caller's mutable value. A call needs no address-of operator.

Example :: library {
    AddScore :: (score: ref int, points: int) {
        score += points
    }
}

The compiler infers effects and purity. Functions need no separate pure keyword. Runtime calls have a shared depth limit of 64.

Conditions and loops

if selects a branch. Conditions do not require parentheses.

Example :: library {
    Message :: (health: int) -> string {
        message := ""
        if health <= 0 {
            message = "Game over"
        } else {
            message = "Continue"
        }
        return message
    }
}

switch evaluates its value once. Cases do not fall through. An empty case: is the default.

Example :: library {
    DamageFor :: (level: int) -> int {
        damage: int = 0
        switch level {
            case 1:
                damage = 10
            case 2:
                damage = 20
            case:
                damage = 30
        }
        return damage
    }
}

while repeats while its condition is true. break leaves a loop. continue starts the next iteration.

Example :: library {
    Run :: () {
        remaining: int = 5
        while remaining > 0 {
            remaining -= 1
            if remaining == 2 { continue }
            if remaining == 0 { break }
        }
    }
}

A range with ..< excludes its upper bound. A range with .. includes it. for < visits a range in reverse order.

Example :: library {
    Run :: () {
        score: int = 0
        for i in 0..<4 { score += i } // 0, 1, 2, 3
        for i in 1..3 { score += i }  // 1, 2, 3
        for < i in 0..<4 { score += i } // 3, 2, 1, 0
    }
}

Ranges do not reverse automatically. A descending constant range such as 10..0 is an error.

Arrays and maps

An array type ends in []. Array literals use square brackets. An empty array needs an explicit element type.

Example :: library {
    Run :: () {
        scores: int[] = [10, 20, 30]
        empty: int[] = []
        first := scores[0]
        scores[1] = 25
        scores = array_add(scores, 40)
    }
}

Array indices start at zero. An index outside the array fails the invocation. Collection functions such as array_add return a value. Assign that value to keep the change.

Arrays have value semantics. Changing a copy leaves the original unchanged. Appending to an owned local array and writing its elements update that local storage in place.

Example :: library {
    Run :: () {
        original: int[] = [1, 2]
        copy := original
        copy[0] = 9 // original[0] remains 1.
    }
}

Array iteration binds the item first and an optional index second. Ordinary iteration takes a snapshot before the loop.

Example :: library {
    WeightedTotal :: (scores: int[]) -> int {
        total: int = 0
        for value, index in scores {
            total += value * index
        }
        return total
    }
}

Reference iteration changes the items of a mutable owned array. The loop cannot access the source array directly or suspend.

Example :: library {
    Run :: () {
        scores: int[] = [10, 20, 30]
        for value: ref in scores {
            value += 10
        }
    }
}

A map declares separate key and value types. Check a key before reading it. A missing key fails the lookup.

Example :: library {
    Run :: () {
        scores: Map<string, int> = {"Player": 10, "Rival": 20}
        scores["Player"] = 30
        score: int = 0
        if map_has(scores, "Rival") {
            score = scores["Rival"]
        }
        scores = map_remove(scores, "Rival")
    }
}

Map iteration visits a snapshot in insertion order. Replacing a value keeps the key's position. Map equality compares associations independently of order.

Example :: library {
    Total :: (scores: Map<string, int>) -> int {
        total: int = 0
        for name, points in scores {
            total += points
        }
        return total
    }
}

Text

String iteration yields one string per Unicode scalar. It does not yield bytes or complete displayed characters that contain several scalars.

Example :: library {
    Run :: () {
        for character in "Aé🐈" {
            // character is "A", then "é", then "🐈".
        }
    }
}

Packages can import core:strings for text operations.

package names
import strings "core:strings"

pub IsImage :: (path: string) -> bool {
    return strings.HasSuffix(path, ".png")
}

ByteLength, Bytes, Slice, Index, Split, Join, TrimSpace and related functions use byte offsets. Slices can split UTF-8 sequences. Case conversion and whitespace checks use ASCII rules.

See Core packages for function signatures and descriptions.

Records and unions

A record gives names and types to its fields. A field without a default must appear in the initializer.

Example :: library {
    ScoreEntry :: struct {
        name: string
        points: int = 0
    }
    Run :: () {
        scoreEntry: ScoreEntry = {name: "Player"}
        scoreEntry.points = 10
    }
}

Authored record fields currently support scalar values. Arrays, unions and nested records are not available as authored record fields.

A tagged union stores one alternative at a time. An alternative can have a payload.

Example :: library {
    AttackState :: union {
        Idle | Windup(remaining: number) | Active(damage: int)
    }
    Run :: () {
        ready := false
        countdown: number = 0.0
        health: int = 100
        phase := AttackState.Windup(0.3)
        switch phase {
            case .Idle:
                ready = true
            case .Windup(remaining):
                countdown = remaining
            case .Active(damage):
                health -= damage
        }
    }
}

A switch over a finite union must cover every alternative or include case:. Union values need an initializer. ECS component fields cannot contain unions.

is tests and narrows a union value. as T extracts an optional T. A failed extraction gives nil. A successful extraction preserves zero, false and empty text as present values.

Example :: library {
    Run :: () {
        total: number = 0.0
        result: number | Cancelled = 0
        if result is number amount {
            total += amount
        }

        amount := result as number
        if amount {
            total += amount
        }
    }
}

Packages and visibility

A package is a folder of .chibi files with the same package header. Sibling files share functions, constants, records and unions. Create score/Bonus.chibi in your package root:

package score
// score/Bonus.chibi

Twice :: (points: int) -> int { return points * 2 }
pub Reward :: (points: int) -> int { return Twice(points) + 5 }

Declarations are private to the package unless pub exports them. Other packages can call Reward but cannot call Twice. Create rewards/Main.chibi beside the score folder:

package rewards
// rewards/Main.chibi
import score "project:score"

pub StartingReward :: () -> int {
    return score.Reward(10)
}

Import aliases belong to their file. Sibling files do not inherit them. pub can export functions, constants, records and unions. It follows any attributes and precedes the declaration name.

Game projects currently use named library blocks for reusable functions. Their names resolve through the project catalog.

Scoring :: library {
    Reward :: (points: int) -> int { return points * 2 }
}

A game calls this function as Scoring.Reward(10). Library, behavior and system blocks do not take pub.

Generics and compile-time values

$T binds a type from an argument. Later uses of T refer to that type. $N: int binds an integer that must be known at compilation.

Example :: library {
    Identity :: (value: $T) -> T { return value }
    Scale :: (value: $T, $N: int) -> T { return value * N }
}

Ordinary functions can calculate constants when their inputs and operations are available at compilation.

Example :: library {
    Factorial :: (n: int) -> int {
        if n <= 1 { return 1 }
        return n * Factorial(n - 1)
    }

    Size :: Factorial(5)
}

Compile-time execution supports scalar and type values, authored calls, locals, assignment, if and while. It does not support arrays, for, closures or native calls. Each evaluation has a 65,536-step budget and a 128-call limit.

Generic package functions currently specialize only within their package. Qualified game-library calls can specialize across library boundaries.

Behaviors and state

A behavior reacts to events on an entity. self names that entity. Declarations at the behavior root persist between events.

Lifetime :: behavior {
    elapsed: number = 0.0
    lifetime: number = 3.0

    on Tick :: (dt: s) {
        elapsed += dt
        if elapsed >= lifetime {
            destroy_entity(self)
        }
    }
}

A handler lists the payload fields that it reads, with their types. Fields match by name, so a handler can list a subset in any order. A handler that reads no payload fields writes ().

Timer :: behavior {
    elapsed: number = 0.0
    on Begin :: () {
        elapsed = 0.0
    }
    on Tick :: (dt: s) {
        elapsed += dt
    }
}

A handler cannot read unlisted payload fields or event. The handler can change a payload parameter only when the event declares a reference. A written unit must match the payload field's unit.

An explicit retain binding keeps private state in the enclosing behavior attachment or system registration. A helper call does not create a new owner.

Counter :: behavior {
    visits: retain int = 0
}

Use components for entity-visible state. Use invocation locals for temporary work. All matches of one system share its retained state.

Live replacement preserves matching retained values. New or incompatible bindings use their defaults. Replacement cancels old continuations and tasks. An explicit restart resets the owner's retained state.

Components and systems

A component declares data attached to an entity.

Health :: component {
    current: int
    maximum: int
}

Paths read and write reflected component fields. A component path used as a condition tests whether the component exists.

Damage :: behavior {
    on Begin :: () {
        if self.Health && self.Health.current > 0 {
            self.Health.current -= 1
        }
    }
}

A system runs its body for each matching entity. Its header names the required components. ? makes a component optional. without excludes components.

EmitterControl :: system(emitter: ParticleEmitter, trigger: Aim?) without Collider
    on Tick :: (dt: s) {
    if trigger {
        emitter.Active = trigger.Firing
    }
    emitter.Rate += dt
}

The optional on Tick clause names the step fields that the system reads. Only the system body can read them. Pass a step value to helpers that need it. Systems cannot read event. Omit the clause when the body needs no step fields.

Optional component fields need a presence guard. An await invalidates the proof, so check presence again after suspension.

System-body locals belong to each query invocation. They survive suspension until that invocation completes. Entity state belongs in components when it must outlive the invocation.

A reduction collects contributions to a numeric component field. It publishes them after the system batch completes.

ApplyDamage :: system(projectile: Projectile) {
    reduce projectile.Target.Health.current += -projectile.Damage
}

A reduction producer cannot otherwise read or write the reduced component. Ordinary reductions replay contributions in stable system/query order.

Input and named entities

Input actions come from the project's input map. .held stays true while a source is down. .pressed is true for the fixed step after a press.

BoostEmitter :: behavior {
    on Tick :: () {
        self.ParticleEmitter.Active = input.Boost.held
    }
}

globals exposes scene entities with authored global names. An unknown name is a source error. A declared name absent from the current scene is a runtime error.

CameraFollow :: behavior {
    on Tick :: () {
        self.Transform = globals.Player.Transform
    }
}

A global member is a read-only entity reference. Its writable components can still change. Assigning a global entity to a variable captures its current handle rather than a live binding.

A root-level bind maintains a component field as its sources change.

LinkedEmitter :: behavior {
    bind self.ParticleEmitter.Active = input.Boost.held
}

Waiting and tasks

await suspends the current continuation until an operation completes. Other engine work continues. An awaited call can declare its result.

Spawner :: behavior {
    on Begin :: () {
        await delay(1)
        created := await spawn_prototype(Emitter)
        created.ParticleEmitter.Parent = self
    }
}

Calling a waiting function without await starts a task. The task runs until its first suspension, then continues alongside its caller.

Charger :: behavior {
    Charge :: (seconds: number) -> number {
        await delay(seconds)
        return seconds * 2
    }

    on Begin :: () {
        charging := Charge(1)
        cancel charging after 2
        result := await charging
        if result is not Cancelled {
            self.Health.current += int(result)
        }
    }
}

Awaiting task<T> gives T | Cancelled. Cancellation never becomes a default successful value. if taskHandle tests whether a task is running.

yield resumes on the next update. cancel taskHandle stops the task and its children. cancel taskHandle after seconds sets a deadline relative to the task's original start time.

Task handles belong to the entity or system registration that started them. Removing that owner stops its tasks. Dropping the last handle does not cancel a running task.

Units

Numeric parameters and results can declare dimensions. The compiler checks known dimensions at calls, assignments and returns.

Example :: library {
    Distance :: (speed: u/s, elapsed: s) -> u {
        return speed * elapsed
    }

    ChargeRate :: (charge: number charge, elapsed: s) -> number charge/s {
        return charge / elapsed
    }
}

Known unit names use number storage. An explicit type can precede the unit, such as float u/s. Custom single dimensions need an explicit numeric type. Units do not change runtime storage.

Tests and formatting

@test marks a package-level function with no parameters and no results. assert fails the test when its condition is false.

package scoring

Double :: (points: int) -> int { return points * 2 }

@test
DoublesPoints :: () {
    assert(Double(3) == 6, "three doubles to six")
}

Run tests and format source with the command line tools.

chibi test path/to/packages
chibi fmt path/to/project
chibi check path/to/project

Tests run without a game. They cannot wait or start tasks. See Testing and Toolchain for commands and platform limits.

Current limits

Some language features remain unavailable:

  • Anonymous function values and closures.
  • Array, union and nested-record fields in authored records.
  • Union fields in ECS components.
  • Exported generic specialization between packages.
  • Embedded NUL bytes and multiline string literals.

These examples describe the language accepted by the native frontend. The authored stage-one package compiler supports a smaller subset. It still needs explicit local types and does not compile maps or reference iteration. It supports integer switches, range loops, indexed loops, reverse loops and literal parameter defaults.
